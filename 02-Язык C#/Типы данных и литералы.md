# Типы данных и литералы

> [!abstract] Коротко
> Тип в C# отвечает на три вопроса: сколько байт занимает значение, какие операции с ним допустимы и где оно живёт — в самом месте объявления (значимые типы) или в куче по ссылке (ссылочные). Встроенные ключевые слова `int`, `double`, `string` — это псевдонимы типов из BCL (`System.Int32`, `System.Double`, `System.String`), полностью взаимозаменяемые. Литерал — это способ записать значение в коде, и у него есть собственный тип: `1` — это `int`, `1.0` — `double`, `1m` — `decimal`, и от этого зависит результат выражения.

## Зачем это нужно

Выбор типа — первое решение в любой строке кода, и оно неотменяемо-дорогое в двух случаях: когда речь о деньгах (`double` вместо `decimal` даёт расхождения с бухгалтерией) и когда речь об идентификаторах (`int` вместо `long` однажды заканчивается остановкой сервиса на 2,1 миллиарде записей).

Второй мотив — понимать, что выражение вычисляется в типе операндов, а не в типе переменной, которой присваивается результат:

```csharp
double half = 1 / 2;
Console.WriteLine(half);      // Вывод: 0 — а ожидали 0,5
```

Здесь оба операнда `int`, деление целочисленное, результат `0`, и только потом он расширяется до `double`. Такие ошибки не ловятся компилятором и живут в коде годами.

## Две категории типов

```
                    типы C#
                       │
        ┌──────────────┴──────────────┐
        │                             │
  значимые (value)            ссылочные (reference)
        │                             │
  ┌─────┴─────┐            ┌──────────┼──────────┐
простые    struct        class     interface   delegate
enum       кортежи       record    string      массивы
           record struct           object
```

Разница в семантике: значимый тип при присваивании **копируется**, ссылочный — копируется только ссылка, и оба имени указывают на один объект.

```csharp
struct PointS { public int X; }
class PointC { public int X; }

var s1 = new PointS { X = 1 };
var s2 = s1;              // копия значения
s2.X = 99;
Console.WriteLine(s1.X);  // Вывод: 1 — исходник не тронут

var c1 = new PointC { X = 1 };
var c2 = c1;              // копия ссылки
c2.X = 99;
Console.WriteLine(c1.X);  // Вывод: 99 — тот же объект
```

Подробный разбор, включая расположение в памяти, упаковку и выбор между `struct` и `class`, — [[Value types vs Reference types]] и [[Записи (record) и структуры]]. Здесь важно запомнить: **все встроенные числовые типы, `bool` и `char` — значимые. `string` и `object` — ссылочные.**

| `byte` | `System.Byte` | 1 | 0 … 255 | 0 |

### Псевдонимы: `int` или `Int32`?

Полностью эквивалентны, `int` — просто синоним. Соглашение .NET: **ключевое слово в коде, имя BCL — когда важен размер или когда обращаешься к статическим членам**:

```csharp
int a = 5;                       // так пишут
System.Int32 b = 5;              // так не пишут
Console.WriteLine(int.MaxValue); // но статические члены — через ключевое слово, оно тоже работает
Console.WriteLine(nameof(Int32));// имя BCL нужно в рефлексии и диагностике
```

Единственное место, где путаница реальна: в именах методов BCL используются имена типов из BCL — `BinaryReader.ReadInt32()`, `Convert.ToInt64()`, `BitConverter.ToSingle()`. Никакого `ReadInt()` не существует.

### Какой тип выбирать

- **Целые:** `int` по умолчанию — так спроектированы API .NET (`Length`, `Count`, индексы). `long` — для идентификаторов, счётчиков, размеров файлов, времени в миллисекундах. `byte`/`short` — только для экономии памяти в больших массивах или для протоколов: в арифметике они всё равно расширяются до `int`, выигрыша по скорости нет.
- **Дробные:** `double` — измерения, статистика, проценты, координаты. `decimal` — деньги, всегда. `float` — только когда важен объём (текстуры, аудио, ML-модели) и точности 7 знаков достаточно.
- **Беззнаковые (`uint`, `ulong`):** избегать в публичных API. Они не спасают от отрицательных значений (`(uint)(-1)` даст 4 294 967 295), плохо сочетаются со знаковыми в арифметике и не имеют аналога в некоторых языках и БД. Уместны в битовых операциях и хешах.

## Литералы

Литерал — значение, записанное прямо в коде. У него есть тип, выведенный по форме записи, и это источник неожиданностей.

```csharp
// Целые: по умолчанию int; если не влезает — uint, long, ulong (первый подходящий)
var i  = 42;          // int
var l  = 42L;         // long
var u  = 42U;         // uint
var ul = 42UL;        // ulong
var big = 10_000_000_000;   // не влезает в int → компилятор выбирает long

// Системы счисления и разделители
int hex = 0xFF_FF;            // 65535
int bin = 0b1010_1010;        // 170
long card = 4_276_3800_1234_5678;

// Дробные: по умолчанию double
var d  = 3.14;        // double
var f  = 3.14f;       // float  — суффикс обязателен, иначе ошибка присваивания
var m  = 3.14m;       // decimal
var e  = 1.5e-3;      // double, 0,0015

// Символы и строки
char c    = 'A';
char tab  = '\t';
char esc  = '\e';                  // символ escape, ASCII 27 (C# 13); раньше писали '\u001b'
char uni  = '\u00E9';              // é
string s  = "текст";
string v  = @"C:\temp\file.txt";   // verbatim: escape-последовательности не работают
string raw = """
              {"id": 1, "name": "Пример"}
              """;                  // raw string literal (C# 11): кавычки не экранируются
ReadOnlySpan<byte> utf8 = "OK"u8;   // UTF-8 литерал (C# 11), сразу в байтах, без конверсии

// Прочее
bool flag = true;
object nothing = null;
```

Суффиксы регистронезависимы, но принято `L`, `UL`, `M` заглавными (строчная `l` визуально путается с единицей) и `f`/`d` строчными.

> [!warning] Литерал `int` в дробном контексте
> ```csharp
> decimal price = 19.99;      // Ошибка CS0664: нет неявного преобразования double → decimal
> decimal ok    = 19.99m;     // так
> float rate    = 0.5;        // Ошибка: double → float неявно нельзя (потеря точности)
> float ok2     = 0.5f;
> double fine   = 1;          // а вот int → double можно: расширяющее преобразование
> ```
> Логика в одном правиле: неявно разрешены только преобразования **без потери информации**. `int → double` безопасно, `double → float` и `double → decimal` — нет. Подробно — [[Приведение типов и checked-unchecked]].

### Строка `"""` вместо экранирования

Raw string literals решают вечную проблему с JSON, регулярками и SQL в коде:

```csharp
// Было
string json = "{\"name\": \"Иван\", \"path\": \"C:\\\\temp\"}";

// Стало
string json2 = """
    {"name": "Иван", "path": "C:\\temp"}
    """;
// Отступ, общий для всех строк и закрывающих кавычек, отрезается автоматически.
// Внутри можно использовать кавычки без экранирования; если нужны три кавычки
// подряд — открывающая последовательность делается длиннее: """" ... """"

// С интерполяцией: число $ задаёт, сколько фигурных скобок начинают выражение
var name = "Иван";
string json3 = $$"""
    {"name": "{{name}}", "template": "{literal braces}"}
    """;
```

## `var`: вывод типа, а не динамика

```csharp
var count = 10;              // компилятор выводит int
var name = "текст";          // string
var items = new List<int>(); // List<int>

// var — это НЕ dynamic и НЕ object:
var x = 10;
// x = "строка";             // Ошибка CS0029: тип x зафиксирован как int
```

`var` — синтаксический сахар этапа компиляции. В IL нет никакой разницы между `var count = 10;` и `int count = 10;`. Ограничения: нельзя для полей класса, нельзя без инициализатора, нельзя присвоить `null` (тип невыводим).

Когда `var` уместен, а когда мешает:

```csharp
// Хорошо: тип очевиден из правой части
var orders = new List<Order>();
var byId = new Dictionary<Guid, Order>();
var config = JsonSerializer.Deserialize<AppConfig>(json);   // тип указан в вызове

// Плохо: тип неочевиден, читателю приходится идти в определение метода
var result = Process(input);        // что это? bool? Order? List<T>?
var value = GetSettings()[key];     // ?
```

Практика в командах: `var`, когда тип виден в той же строке; явный тип, когда он приходит из вызова метода. Настраивается и проверяется через [[Стиль кода, соглашения и .editorconfig]].

Родственная конструкция — **target-typed `new`** (C# 9), работающая в обратную сторону:

```csharp
List<Order> orders = new();                             // тип берётся слева
Dictionary<string, List<int>> map = new() { ["a"] = [1, 2] };
private readonly SemaphoreSlim _gate = new(1, 1);        // особенно полезно для полей
```

## Значения по умолчанию и `default`

```csharp
int a = default;              // 0
bool b = default;             // false
string? s = default;           // null
Guid g = default;              // 00000000-0000-0000-0000-000000000000
DateTime d = default;          // 01.01.0001 00:00:00

// В дженериках без default обойтись невозможно:
static T? FirstOrDefault<T>(IEnumerable<T> source)
{
    foreach (var item in source) return item;
    return default;            // 0 для int, null для string — по типу T
}
```

Значимый тип не может быть `null`, но может быть «нулевым», и это разные вещи. Отсюда практическая проблема: `DateTime` со значением `default` (год 1) и `decimal` со значением 0 неотличимы от «не заполнено». Решение — `Nullable<T>`:

```csharp
int? maybe = null;             // сокращение для Nullable<int>
Console.WriteLine(maybe.HasValue);            // False
Console.WriteLine(maybe ?? -1);               // -1
// Console.WriteLine(maybe.Value);            // InvalidOperationException, если null

DateTime? closedAt = null;     // «ещё не закрыт» — честно выражено типом
```

`Nullable<T>` — структура с двумя полями (значение и флаг), поэтому `int?` занимает 8 байт вместо 4. В БД это отображается на `NULL`, что делает `int?`/`DateTime?` естественным выбором для необязательных колонок. Про `null` для ссылочных типов и статический анализ — [[Nullable reference types]].

## Типы из BCL, которые нужны сразу

Формально не встроенные, но встречаются в первый же день:

| Тип | Что это | Заметка |
|---|---|---|
| `DateTime` | дата и время без смещения | опасен для «моментов времени», см. ниже |
| `DateTimeOffset` | момент времени со смещением от UTC | правильный выбор для событий |
| `DateOnly` / `TimeOnly` | только дата / только время (.NET 6+) | для дней рождения, расписаний |
| `TimeSpan` | интервал | `TimeSpan.FromMinutes(5)` |
| `Guid` | 128-битный идентификатор | `Guid.CreateVersion7()` (.NET 9+) — сортируемый по времени |
| `Uri` | разобранный URL | не хранить URL строкой, если его парсят |
| `decimal` | деньги | уже разобран выше |

Правило по дате: для «когда произошло событие» — `DateTimeOffset` (или `DateTime` строго в UTC), для «календарной даты» — `DateOnly`. Хранить локальное время без смещения — источник багов при переходе на летнее время и при работе из разных часовых поясов. Подробно — [[Дата и время: DateTime, DateTimeOffset, TimeProvider]].

## Псевдонимы типов через `using`

С C# 12 псевдоним можно завести для любого типа, включая кортежи и массивы:

```csharp
using Money = decimal;                       // семантическое имя
using Coordinates = (double Lat, double Lon); // кортеж с именами
using Matrix = double[,];

Coordinates office = (41.2995, 69.2401);
Console.WriteLine(office.Lat);
```

Это не новый тип, а только имя: `Money` и `decimal` взаимозаменяемы, компилятор не помешает сложить деньги с процентами. Настоящая типобезопасность делается через `record struct` — см. [[Записи (record) и структуры]] и [[DDD: тактические паттерны]] (value objects).

> [!warning] Подводные камни
> - **Целочисленное деление.** `1 / 2 == 0`, `5 / 2 == 2`. Ловится тем, что хотя бы один операнд делается дробным: `1 / 2.0`, `(decimal)a / b`.
> - **`float`/`double` для денег.** Разобрано в [[Системы счисления и представление данных]]: 0,1 не представима точно, ошибка накапливается.
> - **`int` для идентификаторов «на вырост».** Смена типа первичного ключа на живой базе — миграция с блокировкой таблицы и правкой всех внешних ключей. `long` с самого начала стоит ноль.
> - **`var` с числовыми литералами в API.** `var timeout = 30;` даёт `int`, а метод ждёт `TimeSpan` — и `30` окажется 30 тиками или 30 миллисекундами в зависимости от перегрузки. Явные типы или `TimeSpan.FromSeconds(30)`.
> - **`char` как «символ».** `char` — 16 бит, эмодзи и редкие письменности в него не влезают и кодируются парой. Перебор строки по `char` может разрезать символ.
> - **Тип по умолчанию у `DateTime`.** `default(DateTime)` — 1 января 0001 года, а не «сейчас» и не `null`. В БД такое значение часто не влезает в тип `timestamp` — отсюда ошибки вставки.
> - **`decimal` не является примитивом CLR.** Арифметика реализована в библиотеке, а не инструкциями процессора: она в 10–20 раз медленнее. Для миллионов операций в цикле это заметно.

> [!example] Как делают в бою
> Типовые решения в продовом коде на .NET 10: деньги — `decimal` в C# и `numeric(19,4)` в PostgreSQL; идентификаторы — `long` для последовательных или `Guid` версии 7 для распределённых; момент времени — `DateTimeOffset` в C# и `timestamptz` в БД, всегда в UTC, преобразование в локальное время — только на границе с UI; необязательные поля — `Nullable<T>`, а не «магические» значения вроде `-1` и `DateTime.MinValue`; величины с единицами измерения (деньги с валютой, вес, длительность) — не «сырой» `decimal`, а `record struct Money(decimal Amount, string Currency)`, чтобы компилятор не дал сложить доллары с сумами.
> Отдельно: включённые `<Nullable>enable</Nullable>` и `<TreatWarningsAsErrors>true</TreatWarningsAsErrors>` в `.csproj` — стандарт для новых проектов; они превращают целый класс ошибок с типами и `null` из ночного инцидента в ошибку компиляции.

## Вопросы с собеседований

> [!question]- Чем значимые типы отличаются от ссылочных?
> Значимый тип содержит само значение, ссылочный — ссылку на объект в управляемой куче. При присваивании и передаче в метод значимый тип копируется целиком, ссылочный копирует только ссылку, поэтому изменения видны через все копии. Значимые типы наследуются от `System.ValueType`, не могут быть `null` (без обёртки `Nullable<T>`), не участвуют в наследовании реализации и сравниваются по значению по умолчанию. Ссылочные типы допускают `null`, наследование, и по умолчанию сравниваются по ссылке (исключения — `string` и `record`, у которых переопределено равенство). Утверждение «структуры лежат на стеке» — упрощение: структура-поле класса лежит в куче внутри объекта, а локальная переменная ссылочного типа лежит на стеке — просто она содержит ссылку.

> [!question]- Почему `1 / 2` даёт 0, а `1 / 2.0` — 0,5?
> Тип выражения определяется типами операндов, а не типом переменной, куда пишется результат. У `1` и `2` тип `int`, поэтому применяется целочисленное деление, отбрасывающее остаток: результат `0`, и он уже потом расширяется до `double` при присваивании. В `1 / 2.0` второй операнд — `double`, поэтому `int` неявно повышается до `double`, и деление выполняется в плавающей точке. То же правило порождает менее очевидный случай: `(double)(a / b)` не спасает — деление уже произошло в целых; нужно `(double)a / b`.

> [!question]- Что такое `var` и чем он отличается от `dynamic`?
> `var` — вывод типа на этапе компиляции: компилятор смотрит на инициализатор, подставляет конкретный тип, и дальше переменная строго типизирована. В IL разницы с явным указанием типа нет вообще, ошибки типов ловятся при сборке. `dynamic` — отложенная до рантайма проверка: обращения к членам разрешаются динамически через инфраструктуру DLR, ошибки проявляются только при выполнении, есть накладные расходы на каждый вызов. `var` можно использовать где угодно в локальном коде, `dynamic` — почти никогда, кроме взаимодействия с COM, динамическим JSON и подобными сценариями. Ещё одно отличие: `var` требует инициализатор и не работает для полей класса.

> [!question]- Когда `decimal`, когда `double`, когда `float`?
> `decimal` — деньги и всё, что должно совпадать с внешним учётом до цента: мантисса целая, масштаб десятичный, поэтому 0,1 представима точно, а точность 28–29 знаков. Цена — 16 байт и программная арифметика, в 10–20 раз медленнее. `double` — измерения, метрики, статистика, геометрия: аппаратная скорость, 15–17 знаков, но двоичная дробь и накопление погрешности, поэтому сравнивать через `==` нельзя. `float` — только там, где важен объём памяти или пропускная способность и хватает 7 знаков: графика, аудио, ML-тензоры. Для денег `float` неприменим ещё и потому, что 7 знаков не хватает даже на сумму в миллион с копейками.

> [!question]- Что такое `Nullable<T>` и как он устроен?
> `Nullable<T>` (сокращённо `T?` для значимых типов) — структура с двумя полями: значение типа `T` и булев флаг `HasValue`. Поэтому `int?` занимает 8 байт вместо 4 и по-прежнему остаётся значимым типом, а не ссылкой. Обращение к `Value` при `HasValue == false` бросает `InvalidOperationException`; безопасные способы — `??`, `GetValueOrDefault()`, `is not null`, pattern matching. Важная особенность: при упаковке `int?` со значением `null` в `object` получается именно `null`, а не «упакованный Nullable», — рантайм обрабатывает этот случай специально. Не путать с nullable reference types: `string?` не создаёт никакой обёртки, это лишь аннотация для статического анализа компилятора.

## Задачи

### Задача 1. Найти четыре ошибки типов

```csharp
decimal price = 19.99;
float discount = 0.15;
int total = price * (1 - discount);
long id = 3_000_000_000;
```

> [!success]- Решение
> ```csharp
> decimal price = 19.99m;              // 1. double → decimal неявно нельзя, нужен суффикс m
> decimal discount = 0.15m;            // 2. то же для float: 0.15 — это double.
>                                      //    И смешивать decimal с float в одном выражении
>                                      //    вообще нельзя: неявного преобразования нет ни в одну сторону
> decimal total = price * (1 - discount);  // 3. результат дробный, в int он не влезает неявно;
>                                          //    и для денег int в принципе неверен
> long id = 3_000_000_000L;            // 4. литерал без суффикса не влезает в int;
>                                      //    здесь компилятор сам выберет long, но суффикс
>                                      //    делает намерение явным и защищает от рефакторинга
> ```
> Общий вывод: тип литерала определяется его записью, а не типом переменной слева. `decimal` не смешивается с `float`/`double` в арифметике — это специально сделано, чтобы нельзя было случайно потерять точность денежного значения.

### Задача 2. Почему не совпадает

```csharp
Console.WriteLine(0.1f + 0.2f == 0.3f);
Console.WriteLine(0.1 + 0.2 == 0.3);
Console.WriteLine(0.1m + 0.2m == 0.3m);
```

Что выведет каждая строка и почему результаты разные?

> [!success]- Решение
> Вывод: `True`, `False`, `True`.
> Третья строка честна: `decimal` хранит десятичный масштаб, 0,1 и 0,2 представимы точно, сумма точно равна 0,3.
> Вторая — классика: у `double` 52 бита мантиссы, 0,1 и 0,2 — бесконечные двоичные дроби, их сумма даёт 0,30000000000000004, что не равно ближайшему представлению 0,3.
> Первая — самое коварное. У `float` всего 23 бита мантиссы, погрешность **больше**, но и шаг между представимыми числами больше: и сумма, и литерал 0.3f округляются к одному и тому же представимому значению, поэтому сравнение случайно проходит. Это ровно тот случай, из-за которого нельзя проверять корректность работы с плавающей точкой экспериментом «у меня совпало»: меньшая точность дала «правильный» ответ, а большая — «неправильный».

### Задача 3. Выбрать типы для модели

Опиши поля для сущности «платёж»: идентификатор, сумма, валюта, момент создания, момент подтверждения (может отсутствовать), количество попыток, признак тестового платежа, внешний идентификатор в платёжной системе.

> [!success]- Решение
> ```csharp
> public sealed class Payment
> {
>     public long Id { get; init; }                       // не int: платежи растут быстро
>     public decimal Amount { get; init; }                // деньги — только decimal
>     public string Currency { get; init; } = "UZS";       // ISO-код; лучше — enum или value object
>     public DateTimeOffset CreatedAt { get; init; }       // момент времени со смещением
>     public DateTimeOffset? ConfirmedAt { get; set; }     // отсутствие выражено типом, а не «нулём»
>     public int AttemptCount { get; set; }                // счётчик в разумных пределах — int
>     public bool IsTest { get; init; }                    // никакой строки "true"/"false"
>     public string? ExternalId { get; set; }              // может отсутствовать до отправки
> }
> ```
> Ключевые решения: `long` для идентификатора — потому что смена типа PK на живой базе крайне дорога; `decimal` для суммы — обязательно; `DateTimeOffset` вместо `DateTime` — чтобы не терять смещение и не зависеть от часового пояса сервера; `DateTimeOffset?` вместо `DateTime.MinValue` в роли «нет значения» — иначе появляется магическое значение, которое рано или поздно попадёт в отчёт; `string?` для внешнего идентификатора — честная аннотация, что до отправки его нет (при включённых nullable reference types компилятор это проверит). Следующий шаг зрелости — `Money` как `record struct` с суммой и валютой, чтобы нельзя было сложить сумы с долларами; это тема [[Записи (record) и структуры]].

## Итог

- Типы делятся на значимые (копируются по значению) и ссылочные (копируется ссылка). Все числовые, `bool`, `char` — значимые; `string`, `object` — ссылочные.
- `int`, `double`, `string` — псевдонимы `System.Int32`, `System.Double`, `System.String`, полностью равнозначные.
- Тип выражения определяется операндами, а не переменной слева: `1 / 2` — это `0`.
- У литерала есть тип: `1` — `int`, `1.0` — `double`, `1m` — `decimal`, `1f` — `float`. Неявно разрешены только преобразования без потери информации.
- `var` — вывод типа при компиляции, не динамика; `new()` — тот же вывод в обратную сторону.
- Значимый тип не может быть `null`, но имеет значение по умолчанию; «нет значения» выражается через `Nullable<T>`, а не магическими константами.
- Деньги — `decimal`, идентификаторы — `long` или `Guid` v7, момент времени — `DateTimeOffset` в UTC.
