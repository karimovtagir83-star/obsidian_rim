# Синтаксис и структура программы

> [!abstract] Коротко
> Это карта всего, что в C# считается «синтаксисом»: лексика и структура файла, типы и литералы, `const`/`readonly`, операторы, ветвление, циклы, массивы, методы с `ref`/`out`/`in`, `namespace`/`using`, индексаторы. Каждая из этих тем компилятор проверяет сам — агент выдаёт корректный код за секунды. Ценность заметки не в синтаксисе, а в местах, где код компилируется, но делает не то, что кажется: приоритеты операторов, `readonly` на ссылке, `var` в денежном коде, `&` вместо `&&`.

## Зачем это знать

Ревью синтаксически корректного, но семантически неверного кода — рутина каждого дня: агент пишет то, что компилируется и выглядит разумно, а ловушка обнаруживается только при чтении логики. Держать в голове нужно не грамматику C#, а список мест, где «компилируется» ≠ «работает правильно»: целочисленное деление, приоритет `&`/`&&`, ковариантность массивов, `readonly`-поле-ссылка, `const` в публичном API библиотеки. Второй мотив — стиль: код, который правят разные люди и агент, должен быть предсказуем по форме (`.editorconfig`, Allman-скобки, `var`-соглашения), иначе ревью тонет в спорах о форматировании вместо содержания.

## Модель

### Файл и структура

Порядок верхнеуровневых элементов `.cs`-файла фиксирован: `extern alias` → `using` (сначала `global using`) → атрибуты `[assembly: …]` → `namespace` → типы. Нарушение — ошибка компиляции, а не стиль.

```csharp
namespace Billing.Domain;                 // file-scoped (C# 10) — стандарт для net8.0

public sealed class Invoice
{
    public required int Number { get; init; }
}
```

File-scoped `namespace X;` — умолчание нового кода: один namespace на файл, без лишнего уровня отступа. Top-level statements (C# 9) убирают шаблонный `Main` для `Program.cs`: компилятор сам заворачивает код в `internal partial class Program` с методом `<Main>$`. Практическое следствие — для интеграционных тестов нужен маркер `public partial class Program;` в конце файла, иначе `WebApplicationFactory<Program>` не скомпилируется (`Program` внутренний).

### Типы и литералы

Все встроенные числовые типы, `bool`, `char` — значимые (копируются целиком); `string`, `object` — ссылочные (копируется ссылка). У литерала есть собственный тип независимо от того, куда он присваивается:

```csharp
double half = 1 / 2;      // Вывод: 0 — оба операнда int, деление целочисленное
decimal price = 19.99;    // CS0664 — double в decimal неявно нельзя, нужен суффикс m
```

| Домен | Тип | Почему |
|---|---|---|
| Деньги | `decimal` | точный десятичный масштаб, `float`/`double` копят погрешность |
| Идентификатор | `long` или `Guid` v7 | смена `int` → `long` на живой базе — дорогая миграция |
| Момент времени | `DateTimeOffset` (UTC) | `DateTime` без смещения ломается на переходе часовых поясов |
| Отсутствие значения | `Nullable<T>` (`T?`) | не магическое `-1`/`DateTime.MinValue` |

`var` — вывод типа при компиляции, не `dynamic`: в IL разницы с явным типом нет. Ограничения языка: нельзя для полей, параметров, возврата метода, нельзя `var x = null;`.

### Переменные: const, readonly, static readonly

| | `const` | `static readonly` | `readonly` (поле) |
|---|---|---|---|
| Когда вычисляется | компиляция | первое обращение к типу | конструктор |
| Инлайнится у потребителя | **да** | нет | нет |
| Устойчиво к обновлению библиотеки | **нет** | да | да |
| Допустимые типы | примитивы, `string`, `enum`, `null` | любые | любые |

`const` физически вшивается (`ldc.i4.3`) в IL каждого места использования — обновление библиотеки без пересборки потребителя ничего не меняет. `readonly` замораживает только слот: `readonly List<int> _items` спокойно мутируется через `_items.Add(...)`.

### Операторы и выражения

Приоритет операторов не нужно помнить наизусть — нужно ставить скобки там, где приходится вспоминать. Три места, где это регулярно ловит:

```csharp
if (flags & Flags.Admin != 0)     // Ошибка: сначала != , потом &
if ((flags & Flags.Admin) != 0)   // так

if (user != null & user.IsActive) // & — не короткое замыкание, NRE при user == null
if (user != null && user.IsActive)

object o1 = "текст";
object o2 = string.Concat("те", "кст");
Console.WriteLine(o1 == o2);      // False: == разрешается статически, для object — по ссылке
Console.WriteLine(o1.Equals(o2)); // True: Equals виртуален, разрешается в рантайме
```

`&&`, `||`, `??`, `?.` — короткое замыкание, это часть семантики языка, а не оптимизация: на нём держатся все проверки на null и границы. `??` защищает только от `null` слева, не от исключения внутри индексатора (`dictionary["key"]` бросит `KeyNotFoundException`, а не вернёт `null`).

### Ветвление

`if`/`else` последовательны сверху вниз; `else` привязывается к ближайшему незакрытому `if` (dangling else) — лечится только явными скобками. `switch` бывает инструкцией (fall-through запрещён, `break` обязателен) и выражением (C# 8, возвращает значение, полнота проверяется компилятором — CS8509).

| | `switch`-инструкция | `switch`-выражение |
|---|---|---|
| Возвращает значение | нет | да |
| Провал между ветвями | явный `goto case` | невозможен |
| Нет совпадения | молча ничего | `SwitchExpressionException` |
| Проверка полноты | нет | да (CS8509) |

### Циклы

`foreach` — синтаксический сахар: компилятор ищет **форму** (`GetEnumerator`/`MoveNext`/`Current`), а не интерфейс, оборачивает в `try/finally` с `Dispose`. Отсюда: изменение коллекции во время обхода бросает `InvalidOperationException` (защита от тихой порчи данных), а переменная `for`, захваченная в лямбду, — одна на весь цикл (все делегаты видят финальное значение), тогда как переменная `foreach` — новая на каждой итерации (с C# 5).

```csharp
for (int i = 0; i < 3; i++)
    actions.Add(() => Console.Write(i));   // Вывод: 333 — одна i на весь цикл
```

### Массивы, индексаторы, Index/Range

Массив — непрерывный блок в куче с фиксированной длиной; присваивание копирует ссылку, не данные. Массивы ссылочных типов ковариантны — дыра в типобезопасности: `object[] o = new string[1]; o[0] = 42;` компилируется и падает в рантайме (`ArrayTypeMismatchException`).

`Index` (`^1`) и `Range` (`1..^1`) работают по форме — типу достаточно иметь `Length`/`Count` и `this[int]` для индекса, плюс `Slice` для диапазона. Отсюда несогласованность: у `List<T>` есть `^`, но нет `..` (нет `Slice`). Срез массива и строки копирует; срез `Span<T>` — окно в ту же память без аллокации.

### Методы и параметры

Подпись — имя, число и типы параметров с модификаторами; возвращаемый тип в неё **не входит**. По умолчанию всё передаётся по значению — для ссылочных типов копируется сама ссылка:

```csharp
static void ReplaceList(List<int> list) => list = new() { 0 };  // не видно снаружи
static void ModifyList(List<int> list) => list.Add(99);          // видно: тот же объект
```

| Модификатор | До вызова | Пишет метод | Ключевое слово у вызывающего | Когда |
|---|---|---|---|---|
| (нет) | — | нет (копия) | — | по умолчанию |
| `ref` | обязательна | да | `ref` | обмен, изменение на месте |
| `out` | не нужна | обязан | `out` | только `Try*`-паттерн |
| `in` | обязательна | нет | опционально | `readonly struct` от 16 байт |

`in` с обычной (не `readonly`) структурой не ускоряет, а замедляет: компилятор делает защитную копию на каждое обращение, потому что не может доказать отсутствие мутации.

### Namespace и using

`using` не подключает библиотеку (это ссылка на сборку в `.csproj`) — он только сокращает имена. `global using` действует на всю сборку; `ImplicitUsings` — набор, который SDK генерирует сам (`System`, `System.Linq`, `System.Threading.Tasks` и т.д.), поэтому в новых проектах `using System;` не виден. Разрешение имён идёт от ближайшей области наружу: свой тип с именем `Path`, `Task`, `Console` выигрывает у BCL и ломает код в том же пространстве имён неожиданным образом.

## Решения

| Развилка | Выбор | Когда иначе |
|---|---|---|
| `var` или явный тип | `var`, если тип виден в правой части (`new`, каст, литерал); явный тип, если справа вызов метода | денежный/числовой код — явный тип всегда, чтобы не спутать `int` с `decimal` |
| `const` или `static readonly` | `static readonly` для всего, что торчит наружу из библиотеки/модуля | `const` — только internal-константы и места, где он обязателен (`case`, атрибуты, значения по умолчанию) |
| `for` или `foreach` | `foreach` по умолчанию | `for` — нужен индекс, обратный порядок или удаление по позиции |
| `out` или кортеж/record | кортеж для 2–3 значений, `record` — если их больше или набор растёт | `out` — только `Try*` |
| Массив или `List<T>` | `List<T>`, если размер меняется | массив — фиксированный размер, байтовый буфер, `Span<T>`-код |
| `switch`-инструкция или выражение | выражение, если нужен результат | инструкция — если ветви делают побочные эффекты, а не возвращают значение |

> [!example] В ServiceShop
> Проект — `net8.0`/C# 12: file-scoped namespace, `ImplicitUsings=enable`, `Nullable=enable`. Приватные поля — `_camelCase`, читаются через primary constructors (C# 12): `public sealed class OrderService(IOrderRepository repo, TimeProvider clock)` — но параметры конструктора не `readonly` сами по себе, поэтому там, где нужна гарантия неизменности зависимости, поле объявляют явно (`private readonly IOrderRepository _repo = repo;`). `.editorconfig` в корне репозитория фиксирует Allman-скобки, `csharp_style_var_when_type_is_apparent = true` и запрет `var` для примитивов — решает споры о `var` автоматически, а не на ревью. `dotnet format --verify-no-changes` — отдельный шаг CI.

> [!warning] Где ошибаются
> - **`public const` в публичном API модуля.** Значение вшивается в IL потребителя; обновление сборки без пересборки ничего не меняет. Правильно — `public static readonly`.
> - **`readonly` как «неизменяемость».** `readonly List<T> _items` защищает только ссылку — `_items.Add(...)` работает. Нужен `ImmutableArray<T>` или `IReadOnlyList<T>`.
> - **`&` вместо `&&` в проверках на null.** Компилируется, падает не всегда — только когда левая часть ложна, поэтому баг не ловится на первом же тесте.
> - **Дефолтный `if` без скобок.** Висячий `else` привязывается к ближайшему `if`, а не к тому, что подсказывает отступ.
> - **`var` в денежном/числовом коде.** `var timeout = 30;` — `int`, а не `TimeSpan`; `var price = 0;` в расчётах — целочисленное деление вместо `decimal`.
> - **Агент часто:** генерирует синтаксис C# 13/14 (`field`-аксессор, null-conditional присваивание `customer?.Total += 10`, `params ReadOnlySpan<T>`, лямбда-параметры без типа с `ref`/`in`) в проекте на `net8.0`/C# 12 — код не компилируется (`CS8652: функция недоступна в текущей версии языка`), потому что видел эти конструкции в обучающих данных как «современный C#».
> - **Агент часто:** предлагает Minimal API (`app.MapGet(...)`) вместо MVC-контроллеров — в проекте принята MVC-модель, Minimal API там не используется.
> - **Агент часто:** оставляет `switch` по `enum` без ветви `_`/`default` — перечисление можно расширить или получить `(Enum)999`, и код тихо не сработает вместо явной ошибки.

## Проверка на ревью

- В диффе нет синтаксиса C# 13/14 (`field`, `params ReadOnlySpan<T>` в новом коде, `?.=`, `Lock`-тип) — проект на C# 12.
- `public const` в публичном API модуля заменён на `public static readonly`, если значение может измениться.
- Каждый `if` и `else` — в фигурных скобках, даже однострочные.
- В битовых проверках (`flags & Mask`) есть скобки вокруг `&`.
- `switch` по `enum`/паттернам закрыт веткой по умолчанию, а не оставлен «на все известные случаи».
- Нет `var` для примитивов там, где рядом есть арифметика с деньгами или временем.
- `readonly`-поле не выдаётся как доказательство неизменяемости, если оно ссылочного типа.

## Проверь себя

> [!question]- Почему `public const int MaxRetries = 3;` в библиотеке опаснее, чем `public static readonly int MaxRetries = 3;`?
> `const` вычисляется на этапе компиляции и физически инлайнится (`ldc.i4.3`) в IL каждого места использования у потребителя. Обновление библиотеки без пересборки приложения ничего не меняет — приложение продолжает видеть старое значение, вшитое в свой собственный IL. `static readonly` читается через `ldsfld` во время выполнения, поэтому обновление библиотеки долетает до потребителя без его пересборки.

> [!question]- Почему `readonly List<int> _items` не делает объект неизменяемым?
> `readonly` замораживает только слот поля — саму ссылку, а не то, на что она указывает. Присвоить полю новый список вне конструктора нельзя, но вызвать `_items.Add(...)`, `_items.Clear()` можно совершенно свободно: это не присваивание полю, а мутация объекта, на который оно ссылается. Реальная неизменяемость требует неизменяемого типа: `ImmutableArray<T>`, `record` с `init`-свойствами.

> [!question]- Чем `switch`-выражение отличается от `switch`-инструкции и что произойдёт, если ни одна ветвь не подошла?
> Выражение возвращает значение и требует, чтобы ветви покрывали все случаи (иначе предупреждение CS8509); инструкция ничего не возвращает, и `break` в ней обязателен. Если во время выполнения выражения ни один паттерн не подошёл, бросается `SwitchExpressionException` — поэтому `switch` по `enum` или паттернам без явной ветви `_` в реальном коде опасен: расширение перечисления или неожиданное значение уронит выполнение в рантайме, а не на этапе сборки.

> [!question]- Почему `o1 == o2` для двух одинаковых по содержанию строк, объявленных через `object`, даёт `false`?
> Операторы в C# — статические методы, и перегрузка `==` выбирается компилятором по статическим типам операндов, а не по фактическим. Для переменных типа `object` выбирается сравнение ссылок, перегруженный `String.op_Equality` не рассматривается вовсе. `Equals`, наоборот, виртуален и разрешается в рантайме по фактическому типу — поэтому `o1.Equals(o2)` даёт `true`. В обобщённом коде и при работе через базовые типы сравнивать нужно через `Equals` или `EqualityComparer<T>.Default`.

## Разбор

### Упражнение 1. Что не так

```csharp
public static class Fees
{
    public const decimal ServiceFeePercent = 1.5m;
}

// в другом модуле
var withFee = amount * (1 + Fees.ServiceFeePercent / 100);
```

Через месяц `ServiceFeePercent` меняют на `2.0m` и выкатывают библиотеку без пересборки вызывающего кода. Что увидит вызывающий код и почему?

> [!success]- Разбор
> Вызывающий код продолжит считать по `1.5m`, хотя в новой версии библиотеки значение уже `2.0m`. `const decimal` не является IL-литералом (`decimal` не примитив CLR), компилятор эмитит `initonly`-поле с `[DecimalConstantAttribute]`, но Roslyn у потребителя всё равно инлайнит значение при компиляции — то есть проблема ровно та же, что у `const int`, только механизм чуть другой. Фикс: `public static readonly decimal ServiceFeePercent = 1.5m;` — тогда потребитель читает актуальное значение через `ldsfld` при каждом обращении.

### Упражнение 2. Ревью PR от агента

Агент прислал такой diff в проекте на `net8.0`:

```csharp
public class Temperature
{
    public int Celsius
    {
        get => field;
        set => field = value < -273 ? throw new ArgumentOutOfRangeException() : value;
    }
}
```

Что вернуть на доработку?

> [!success]- Разбор
> `field`-аксессор — это C# 14, проект собирается компилятором для C# 12 (`net8.0`) — код не скомпилируется (`CS8652`). Агент подобрал синтаксис из обучающих данных, где он описан как «современный способ», не проверив версию языка проекта. Правка для C# 12 — обычное приватное поле:
> ```csharp
> public class Temperature
> {
>     private int _celsius;
>     public int Celsius
>     {
>         get => _celsius;
>         set => _celsius = value < -273
>             ? throw new ArgumentOutOfRangeException(nameof(value))
>             : value;
>     }
> }
> ```
> Отдельно стоит проверить, что `LangVersion` в `.csproj` действительно закреплён на 12, а не `latest` — иначе такой код иногда всё же проходит сборку локально с более новым SDK и падает только в CI с зафиксированной версией.

## Итог

- Синтаксис C# сам по себе не место для ошибок — их ловит компилятор. Ловушки там, где код компилируется, но означает не то: приоритеты операторов, `readonly` на ссылке, статическое разрешение `==`, `const` в публичном API.
- `var` — вывод типа, не динамика; выбор между `var` и явным типом — вопрос читаемости, а не производительности.
- `const` инлайнится и ломает версионирование библиотек; `static readonly` — безопасный выбор для всего, что может измениться.
- `foreach` разворачивается по форме (`GetEnumerator`/`MoveNext`), а не по интерфейсу — отсюда и защита от изменения коллекции во время обхода, и разница в захвате переменных `for` и `foreach`.
- Проект — `net8.0`/C# 12: синтаксис C# 13/14 (`field`, null-conditional присваивание, `params ReadOnlySpan<T>`) в код не идёт, даже если агент предлагает его как «более современный».

> [!info] Куда идёт индустрия
> C# 13 добавил `params ReadOnlySpan<T>` (вызов без аллокации массива) и escape-символ `\e`; C# 14 — `field`-аксессор для свойств, null-conditional присваивание (`customer?.Total += 10`), модификаторы `ref`/`out`/`in`/`scoped` у параметров лямбд без явного типа и составные операторы (`operator +=`) для своих типов. В `net8.0` ничего из этого недоступно — но встретится в статьях, ответах агента и при апгрейде на .NET 10.
