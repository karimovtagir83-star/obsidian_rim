# Индексаторы, Index и Range

> [!abstract] Коротко
> Индексатор — свойство, к которому обращаются через квадратные скобки: `collection[key]`. Объявляется как `public T this[int index] { get; set; }` и может принимать любые типы и любое число параметров. Отдельная тема — типы `System.Index` (`^1` — «первый с конца») и `System.Range` (`1..^1` — срез), появившиеся в C# 8. Компилятор поддерживает их не через интерфейс, а по форме: если у типа есть `Length`/`Count` и подходящий индексатор или метод `Slice`, синтаксис `x[^1]` и `x[1..3]` начинает работать автоматически.

## Зачем это нужно

Индексаторы делают свои типы похожими на встроенные коллекции: `cache["key"]`, `matrix[row, col]`, `config["Logging:LogLevel"]`. Это не украшение — это ожидаемая форма обращения, которую читатель понимает без документации.

`Index` и `Range` убирают самый частый источник ошибок «на единицу»:

```csharp
// Было
var last = items[items.Length - 1];
var middle = items.Skip(1).Take(items.Length - 2).ToArray();

// Стало
var last = items[^1];
var middle = items[1..^1];
```

## Свои индексаторы

```csharp
public sealed class Matrix
{
    private readonly double[] _data;
    private readonly int _cols;

    public Matrix(int rows, int cols) => (_data, _cols) = (new double[rows * cols], cols);

    public int Rows => _data.Length / _cols;
    public int Cols => _cols;

    // Индексатор с двумя параметрами
    public double this[int row, int col]
    {
        get => _data[row * _cols + col];
        set => _data[row * _cols + col] = value;
    }
}

var m = new Matrix(2, 3);
m[1, 2] = 5.5;
Console.WriteLine(m[1, 2]);        // Вывод: 5,5
```

Индексатор может принимать любой тип и иметь перегрузки:

```csharp
public sealed class Settings
{
    private readonly Dictionary<string, string> _byName = new(StringComparer.OrdinalIgnoreCase);
    private readonly List<string> _ordered = [];

    public string this[string name]                  // доступ по имени
    {
        get => _byName.TryGetValue(name, out var v) ? v : throw new KeyNotFoundException(name);
        set { _byName[name] = value; _ordered.Add(name); }
    }

    public string this[int position] => _ordered[position];   // доступ по позиции, только чтение
}
```

Технические детали: у индексатора нет собственного имени, в IL он превращается в свойство `Item` с методами `get_Item`/`set_Item` (имя можно поменять атрибутом `[IndexerName]`, что нужно только для interop). Индексаторы объявляются в интерфейсах, могут быть виртуальными и абстрактными, могут иметь разные модификаторы доступа у геттера и сеттера. Статических индексаторов в C# нет.

Когда индексатор, а когда метод: индексатор уместен, если операция ощущается как «взять элемент по ключу» — быстро, без побочных эффектов, без вычислений. Если за скобками стоит запрос к базе, вычисление или мутация, нужен метод с говорящим именем: `GetOrCreate(key)`, `LoadAsync(id)`. Индексатор, делающий сетевой вызов, — обман читателя.

## Index: индекс с конца

```csharp
int[] data = [10, 20, 30, 40, 50];

Index first = 0;                 // неявное преобразование из int
Index last = ^1;                 // оператор ^ создаёт Index с IsFromEnd = true
Console.WriteLine(data[last]);   // Вывод: 50

Console.WriteLine(new Index(1, fromEnd: true).Equals(^1));   // True

// ^0 — это «за последним элементом», допустимо только как граница диапазона
// Console.WriteLine(data[^0]);          // IndexOutOfRangeException
Console.WriteLine(data[..^0].Length);    // 5 — весь массив
```

`Index` — структура с двумя полями: смещение и флаг «с конца». Компилятор превращает `data[^1]` в `data[data.Length - 1]`, поэтому накладных расходов нет.

## Range: срезы

```csharp
Range all = ..;               // всё
Range head = ..3;             // [0, 3)
Range tail = 2..;             // [2, Length)
Range middle = 1..^1;         // без первого и последнего
Range fixedRange = 1..4;      // [1, 4)

int[] slice = data[1..4];                    // [20, 30, 40] — НОВЫЙ массив (копия)
string part = "abcdef"[2..4];                 // "cd" — вызывается Substring
Span<int> view = data.AsSpan()[1..4];         // окно в тот же массив, без копии

// Разбор диапазона руками — когда нужно посчитать смещение
var (offset, length) = middle.GetOffsetAndLength(data.Length);
Console.WriteLine($"{offset} {length}");      // Вывод: 1 3
```

Границы диапазона: начало включительно, конец исключительно — та же конвенция, что у `Substring(start, length)` в терминах позиций и у срезов в Python. Это соглашение делает `a[..i]` и `a[i..]` идеальным разбиением без пересечений и пропусков.

### Как компилятор поддерживает Index и Range

Никакого интерфейса нет — работает распознавание по форме (pattern-based), как у `foreach`:

**Для `Index`** тип должен иметь:
- свойство `Length` или `Count` типа `int`;
- индексатор, принимающий `int` (или собственный индексатор `this[Index]`).

**Для `Range`** тип должен иметь:
- `Length`/`Count`;
- метод `Slice(int start, int length)` (или собственный индексатор `this[Range]`).

```csharp
public sealed class Buffer
{
    private readonly int[] _items;
    public Buffer(int[] items) => _items = items;

    public int Count => _items.Length;               // 1. счётчик
    public int this[int index] => _items[index];      // 2. индексатор по int
    public Buffer Slice(int start, int length)        // 3. срез
        => new(_items[start..(start + length)]);

    public override string ToString() => string.Join(",", _items);
}

var buffer = new Buffer([1, 2, 3, 4, 5]);
Console.WriteLine(buffer[^2]);          // Вывод: 4 — работает благодаря Count + this[int]
Console.WriteLine(buffer[1..3]);        // Вывод: 2,3 — работает благодаря Slice
```

Именно так поддержку получают `string` (`Length` + `Substring` через специальную обработку), массивы, `Span<T>`/`Memory<T>`.

> [!warning] `List<T>` не поддерживает диапазоны
> ```csharp
> var list = new List<int> { 1, 2, 3 };
> Console.WriteLine(list[^1]);        // работает: есть Count и this[int]
> // var slice = list[0..2];           // Ошибка: у List<T> нет Slice и нет this[Range]
> var slice = list.GetRange(0, 2);                                  // штатный способ
> var span = System.Runtime.InteropServices.CollectionsMarshal.AsSpan(list)[0..2];  // без копии
> ```
> Это регулярный сюрприз: `^` работает, а `..` нет. Причина — отсутствие метода `Slice` у `List<T>`.

## Индексаторы, принимающие Index и Range

Свой тип может объявить их явно — это даёт полный контроль:

```csharp
public sealed class Ring<T>
{
    private readonly T[] _items;
    public Ring(int size) => _items = new T[size];

    public int Count => _items.Length;

    // Кольцевой доступ: индекс не выходит за границы, а заворачивается
    public T this[int index]
    {
        get => _items[((index % Count) + Count) % Count];
        set => _items[((index % Count) + Count) % Count] = value;
    }

    // Собственная обработка Index: приоритетнее, чем автоматическая через Count
    public T this[Index index] => this[index.IsFromEnd ? Count - index.Value : index.Value];
}
```

Если у типа есть и `this[Index]`, и `Count` + `this[int]`, компилятор выберет явный индексатор — это способ задать нестандартную семантику (кольцо, разреженная коллекция, ленивая загрузка).

> [!warning] Подводные камни
> - **`^0` как индекс.** Это позиция «за последним элементом»: допустима как граница среза (`..^0`), но обращение `x[^0]` бросает исключение.
> - **Срез массива копирует.** `array[1..4]` — новый массив и копирование; в горячем коде нужен `AsSpan()[1..4]`.
> - **`List<T>` и `..`.** Не поддерживается: `GetRange` или `CollectionsMarshal.AsSpan`.
> - **Индексатор, бросающий исключение.** `dict[key]` бросает `KeyNotFoundException`, и это стандартное поведение — но в своих типах стоит подумать, не нужен ли `TryGet`-метод: обращение в скобках выглядит дешёвым и безопасным, а исключение в потоке данных — дорого.
> - **Индексатор с побочными эффектами.** `cache[key]`, который лезет в сеть или пишет в лог, ломает ожидания читателя. Такой операции нужно имя.
> - **Диапазон с обратными границами.** `data[4..2]` даёт `ArgumentOutOfRangeException` в рантайме: компилятор такие ошибки не ловит, потому что границы могут быть переменными.
> - **Индексатор вместо словаря.** Класс с одним строковым индексатором поверх словаря обычно не нужен — он просто скрывает `Dictionary` и мешает видеть сложность операций.

> [!example] Как делают в бою
> `Index` и `Range` в прикладном коде используются в основном для читаемости: `path[^4..]` вместо `path.Substring(path.Length - 4)`, `args[1..]` для передачи «остальных аргументов», `line[..idx]`/`line[(idx+1)..]` при разборе строк. В инфраструктурном коде их применяют вместе со `Span<T>`: срез без копирования — основной приём парсеров и сериализаторов.
> Свои индексаторы встречаются реже, чем кажется: в прикладной модели почти всегда правильнее явно названный метод. Оправданные случаи — обёртки над хранилищами вида «ключ-значение» (конфигурация, кеш, заголовки), матрицы и буферы, где обращение по позиции естественно.
> `IConfiguration` из ASP.NET Core — образцовый пример: `config["ConnectionStrings:Default"]` читается мгновенно, а неудачный поиск возвращает `null`, а не исключение, потому что отсутствие настройки — ожидаемая ситуация.

## Вопросы с собеседований

> [!question]- Как компилятор поддерживает `^1` и `1..3` для своих типов?
> По форме, а не через интерфейс. Для `Index` типу достаточно иметь публичное свойство `Length` или `Count` типа `int` и индексатор, принимающий `int`: тогда `x[^1]` компилируется в `x[x.Count - 1]`. Для `Range` дополнительно нужен метод `Slice(int start, int length)`: `x[1..3]` превращается в `x.Slice(1, 2)`. Альтернатива — объявить индексаторы `this[Index]` и `this[Range]` явно; они имеют приоритет и позволяют задать нестандартную семантику. Такой подход по форме (как у `foreach`) выбран потому, что интерфейс нельзя реализовать для `ref struct` вроде `Span<T>`, и потому что он не требует изменений в уже существующих типах вроде массивов и строк. Практическое следствие несогласованности: у `List<T>` есть `Count` и `this[int]`, поэтому `list[^1]` работает, но нет `Slice`, поэтому `list[0..2]` не компилируется.

> [!question]- Чем срез массива отличается от среза `Span<T>`?
> `array[1..4]` создаёт **новый массив** и копирует в него элементы: это аллокация в куче плюс копирование, и изменения в срезе не видны в исходном массиве. `array.AsSpan()[1..4]` создаёт `Span<T>` — структуру из ссылки на начало и длины, то есть окно в ту же память: аллокаций нет, а запись через срез изменяет исходный массив. Отсюда правило: для передачи «части данных» в метод, который только читает или изменяет на месте, используется `Span<T>`/`ReadOnlySpan<T>`; копия нужна лишь тогда, когда результат должен жить независимо от источника. Ограничение `Span<T>` — это `ref struct`: его нельзя хранить в поле класса, использовать в `async`-методе или захватывать в лямбду; для таких случаев есть `Memory<T>`. Для строк аналогично: `s[1..4]` вызывает `Substring` (копия), `s.AsSpan(1..4)` — нет.

> [!question]- Когда индексатор лучше метода, а когда наоборот?
> Индексатор оправдан, когда операция читается как «взять элемент по ключу или позиции»: она дешёвая, детерминированная, без побочных эффектов, и её результат — часть уже существующих данных. Примеры: `matrix[row, col]`, `headers["Content-Type"]`, `config["Section:Key"]`. Метод нужен, когда за обращением стоит работа: запрос к базе, вычисление, создание отсутствующего элемента, асинхронность (индексатор не может быть асинхронным вообще). Квадратные скобки создают у читателя ожидание константной стоимости, и обманывать это ожидание — источник проблем с производительностью, которые никто не замечает на ревью. Дополнительный аргумент за метод: имя. `GetOrCreate(key)` объясняет семантику, а `this[key]` требует читать документацию, чтобы понять, бросает ли он исключение, возвращает ли `null` или создаёт значение.

## Задачи

### Задача 1. Поддержать срезы в своём типе

Есть класс-обёртка над массивом байтов. Сделай так, чтобы работали `buffer[^1]` и `buffer[2..5]`, причём срез не копировал данные.

> [!success]- Решение
> ```csharp
> public sealed class ByteBuffer
> {
>     private readonly byte[] _data;
>     private readonly int _start, _length;
>
>     public ByteBuffer(byte[] data) : this(data, 0, data.Length) { }
>     private ByteBuffer(byte[] data, int start, int length)
>         => (_data, _start, _length) = (data, start, length);
>
>     public int Length => _length;                                   // для Index/Range
>     public byte this[int index] => _data[_start + index];            // для Index
>     public ByteBuffer Slice(int start, int length)                   // для Range
>         => new(_data, _start + start, length);
>
>     public ReadOnlySpan<byte> AsSpan() => _data.AsSpan(_start, _length);
> }
>
> var buffer = new ByteBuffer([1, 2, 3, 4, 5]);
> Console.WriteLine(buffer[^1]);               // Вывод: 5
> Console.WriteLine(buffer[2..5][0]);          // Вывод: 3
> ```
> Идея решения — хранить не копию, а тройку «массив + смещение + длина», ровно как это делает `Span<T>`. Тогда `Slice` создаёт лёгкий объект, ссылающийся на тот же массив, и копирования не происходит. Обрати внимание, что `this[int]` учитывает `_start`: без этого срез возвращал бы элементы с начала исходного массива. Метод `AsSpan` добавлен потому, что для чтения в горячем коде `Span<byte>` всё равно удобнее, а тип-обёртка нужен там, где значение надо хранить в поле — чего `ref struct` не позволяет.

### Задача 2. Найти ошибки

```csharp
var items = new List<string> { "a", "b", "c", "d" };
var lastTwo = items[^2..];
var text = "abcdef";
var chunk = text[4..2];
var arr = new[] { 1, 2, 3 };
Console.WriteLine(arr[^0]);
```

> [!success]- Решение
> Три ошибки.
> `items[^2..]` не компилируется: `List<T>` поддерживает `Index` (есть `Count` и `this[int]`), но не `Range` — нет метода `Slice`. Варианты: `items.GetRange(2, 2)`, `items.TakeLast(2).ToList()` или `CollectionsMarshal.AsSpan(items)[^2..]`, если нужен срез без копирования.
> `text[4..2]` компилируется, но бросает `ArgumentOutOfRangeException` в рантайме: начало диапазона больше конца. Компилятор такие случаи не ловит, потому что в общем случае границы — переменные.
> `arr[^0]` бросает `IndexOutOfRangeException`: `^0` означает позицию «за последним элементом», она допустима только как граница среза (`arr[..^0]` — весь массив). Последний элемент — это `^1`.

## Итог

- Индексатор — свойство с параметрами, в IL становится `get_Item`/`set_Item`; статических индексаторов нет.
- Индексатор уместен для дешёвого доступа по ключу или позиции; за вычислениями, запросами и асинхронностью должен стоять метод с именем.
- `Index` — смещение плюс флаг «с конца»; `^1` — последний элемент, `^0` — только граница среза.
- `Range` — полуоткрытый интервал `[начало, конец)`, поэтому `a[..i]` и `a[i..]` дают точное разбиение.
- Поддержка `Index`/`Range` работает по форме: `Length`/`Count` + `this[int]` для индекса, плюс `Slice` для диапазона.
- Срез массива и строки создаёт копию; срез `Span<T>` — окно в ту же память.
- У `List<T>` работает `^`, но не `..` — нужен `GetRange` или `CollectionsMarshal.AsSpan`.
