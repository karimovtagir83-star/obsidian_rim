# Value types vs Reference types

> [!abstract] Коротко
> В CLR переменная значимого типа **содержит** данные, переменная ссылочного типа содержит **адрес** объекта в куче. Место в памяти определяется не категорией типа, а тем, где живёт владелец: структура-локальная — на стеке, структура-поле класса или элемент массива — внутри объекта в куче. Боксинг — прямое следствие: чтобы значимый тип попал туда, где ожидается ссылка (`object`, интерфейс, `params object[]`), рантайм копирует его в новый объект кучи. Отсюда вытекают семантика копирования, равенство по умолчанию и большая часть скрытых аллокаций в .NET-коде.

## Зачем это знать

Три сценария, где путаница стоит денег или времени на ревью:

1. **Логическая ошибка.** Метод «изменил» структуру, вызывающий код копии не видит — баг не ловится компилятором.
2. **Незаметные аллокации.** Структура, приведённая к интерфейсу или сравненная через `object.Equals`, боксится — в горячем цикле это мегабайты мусора, которые не видны в сигнатуре метода.
3. **Обратная ошибка.** Большая мутабельная структура, скопированная по значению в цикле, дороже класса — «оптимизация» делает хуже.

Правильный выбор struct/class и диагностика лишних копий требуют модели, а не заученной (и неверной) фразы «структуры на стеке, классы в куче».

## Модель

### Иерархия и два вида переменных

```
                    System.Object
                   /             \
      System.ValueType         (ссылочные типы напрямую)
       /          \                class, interface, delegate,
      /            \                string, array, object
System.Enum     структуры (struct)
    |
 enum-типы
```

`ValueType` — сам ссылочный тип (наследник `Object`), это лишь маркер категории плюс переопределённые `Equals`/`GetHashCode`. Структура неявно `sealed`, наследоваться не может, но может реализовывать интерфейсы — с оговоркой ниже про боксинг.

```
Значимый тип:  int x = 42;              Ссылочный тип: object o = new Foo();

  слот x ┌────────────┐                  слот o ┌────────────┐      куча
         │     42     │                         │ 0x7F3A0140 │────▶ ┌───────────┐
         └────────────┘                         └────────────┘      │ header 8B │
                                              (8 байт адреса)        │ MT ptr 8B │
                                                                     │ поля...   │
                                                                     └───────────┘
```

Отсюда всё остальное: присваивание значимого типа копирует данные, присваивание ссылочного — адрес; две структуры всегда независимы, две ссылки могут указывать на один объект. `string` — ссылочный тип, но `==` сравнивает содержимое (перегруженный оператор) и литералы интернируются — не путать это с value-семантикой, `ReferenceEquals` для двух разных по происхождению одинаковых строк всё равно `false`. Подробности строк — [[Строки и работа с текстом]].

### Где физически лежит память

Правило: **значимый тип живёт там, где объявлен**, а не «на стеке».

| Что | Где |
|---|---|
| Локальная переменная значимого типа | стек (или регистр), если не захвачена и не в `async` |
| Локальная переменная ссылочного типа | ссылка на стеке, объект в куче |
| Поле класса (любого типа) | куча, внутри объекта — структура-поле тоже там |
| Элемент массива | куча, внутри массива — массив структур лежит подряд, без отдельных объектов |
| Статическое поле | куча, живёт до конца процесса |
| Захваченная переменная замыкания | куча, поле класса замыкания — даже если это `int` |
| Локальные `async`-метода после `await` | куча, поле объекта состояния |
| `stackalloc` буфер | стек |
| Упакованное значение | куча — результат `box` |

```csharp
void Example()
{
    int a = 5;                     // стек
    Func<int> f = () => a;         // a переехала в поле класса замыкания → куча
    object boxed = a;              // копия в куче — боксинг
}
```

Стек — область на поток (1 МБ по умолчанию), LIFO: выделение — сдвиг указателя (одна инструкция), освобождение бесплатно при выходе из метода. Переполнение даёт `StackOverflowException`, который **нельзя поймать** — для `catch` тоже нужен стек. Куча — общая на процесс, освобождением занимается GC ([[Сборка мусора (GC): как работает]]); выделение там тоже дёшево (сдвиг указателя в gen0), дорога именно последующая сборка и разбросанность объектов по памяти — отсюда правильная формулировка «меньше аллокаций», а не «new — это дорого».

> [!info] Куда идёт индустрия
> С .NET 9+ JIT умеет через escape analysis размещать на стеке объекты ссылочных типов, если доказал, что ссылка не покидает метод. Правило «`new` = куча» стало приблизительным, но полагаться на это в `net8.0` нельзя — оптимизация не гарантирована и не видна в коде.

### Объект в куче и боксинг как копирование в кучу

```
     ссылка ──────┐
                  ▼
  ┌──────────────────────┬────────────────────────┬──────────────────┐
  │  object header 8Б    │  MethodTable ptr 8Б    │  поля экземпляра │
  └──────────────────────┴────────────────────────┴──────────────────┘
  Заголовок 16 байт. Минимальный объект на x64 — 24 байта (выравнивание).
```

Заголовок хранит: индекс sync block (для `lock`/`Monitor`), либо thin lock, либо кешированный `GetHashCode()`, плюс служебные биты GC. У структуры этого заголовка нет вовсе — только поля подряд с выравниванием, поэтому `struct Point { int X, Y; }` — 8 байт там, где объявлена, а не 24+ в куче.

**Боксинг** — упаковка значимого типа в объект: рантайм выделяет объект нужного размера, копирует туда значение, возвращает ссылку. Это ровно тот же механизм создания объекта в куче, что и `new` для класса, только источник данных — существующее значение на стеке или в поле.

```csharp
int value = 42;
object boxed = value;      // IL: box — новый объект в куче, копия 4 байт + заголовок 16Б
int back = (int)boxed;     // IL: unbox.any — копия обратно, ТОЛЬКО в исходный тип
```

Три следствия:

1. Упакованное значение — независимая копия: `a = 100` после `object boxed = a` не меняет `boxed`.
2. Каждая упаковка — новый объект: `ReferenceEquals((object)42, (object)42)` → `false`.
3. Распаковка требует точного типа: `(long)(object)42` — `InvalidCastException`, нужен `(long)(int)(object)42`.

Боксинг случается неявно везде, где значимый тип приводится туда, где CLR ожидает ссылку: `object o = 42`, `IComparable c = 42`, не-обобщённые коллекции (`ArrayList`), `params object[]` (`string.Format`, старое логирование до генераторов), вызов `object.Equals`/`GetHashCode` на структуре без `IEquatable<T>` (`ValueType.Equals` принимает `object` — боксит обе стороны и, если структура не плотно упакована или содержит ссылки, дополнительно перебирает поля рефлексией).

```csharp
// Дженерик с ограничением НЕ боксит — JIT специализирует код под T
static bool AreEqual<T>(T a, T b) where T : IEquatable<T> => a.Equals(b);
// Без ограничения, через интерфейс — боксит оба операнда
static bool AreEqualBoxed(IEquatable<int> a, int b) => a.Equals(b);
```

Особый случай — `Nullable<T>`: `object o = (int?)null` даёт настоящий `null`, а не обёртку (`o.GetType()` бросит `NullReferenceException`); `object o = (int?)5` боксирует само значение `T`, и `o.GetType()` вернёт `System.Int32`, а не `Nullable<Int32>`.

С C# 10 интерполяция строк (`$"..."`) больше **не** боксит значимые типы: компилятор использует `DefaultInterpolatedStringHandler`, который форматирует их напрямую в буфер — в отличие от `string.Format`, который до сих пор уходит в `params object[]`.

## Решения

| Что выбрать | Когда | Последствия |
|---|---|---|
| `class` (по умолчанию) | сущность с идентичностью, размер не критичен, живёт в DI-контейнере | простая модель, но аллокация + минимум 24 байта на экземпляр |
| `readonly record struct` | маленькое (до ~16 байт) иммутабельное значение: id, деньги, координата, диапазон | ноль аллокаций, авто-`IEquatable<T>`, безопасно копируется |
| `struct` (мутабельный) | буфер/аккумулятор в горячем цикле, не покидающий метод | риск багов «изменил копию» через свойство/`foreach`/боксинг — только с явным обоснованием |
| большая `readonly struct` (>16 байт) | массив однотипных данных в вычислительном ядре, всегда передаётся по `in`/`ref` | выигрыш не от «нет аллокаций», а от локальности кеша массива |
| `record class` | сущность/DTO, где нужно равенство по значению, но объект не маленький | остаётся ссылочным типом — аллокация как у `class` |

Простое операционное правило: **пишите `class`, пока профилировщик не покажет, что аллокации мешают**. Любая структура, участвующая в сравнении или служащая ключом словаря, обязана реализовывать `IEquatable<T>` — либо это `readonly record struct`, который сгенерирует его сам ([[Записи (record) и структуры]]).

> [!example] В ServiceShop
> Домен `Alif.ServiceShop.Modules.Orders.Domain` типизирует идентификаторы через `GuidValueObject` (`OrderUuid`, `ClientId`, `ModeratedOfferId` в `Orders.Domain/Order/ValueObjects/`) — но это **классы**, а не `readonly record struct`: каждый id в горячем пути — лишняя аллокация в куче и потенциальный `null`, хотя весь смысл типа был защитить от «перепутал `orderId` с `clientId`» на этапе компиляции. Похожая история с деньгами: суммы (`SubTotalAmount`, `TotalAmount`, `Discount`) в агрегате `Order` хранятся как голый `ulong` — там, где `readonly record struct Money(decimal Amount, string Currency)` дал бы типобезопасность бесплатно, лежит примитив. Базовый `ValueObject` для остальных VO сравнивает поля через рефлексию с кешированием списка свойств — обходной путь вокруг ровно той проблемы, которую `record struct` решает автогенерацией `Equals`/`GetHashCode`/`IEquatable<T>` без единой аллокации.

> [!warning] Где ошибаются
> - **Мутабельная структура за свойством.** `h.C.Inc()` не компилируется (свойство возвращает копию), а `foreach (var c in arr) c.Inc()` компилируется, но ничего не меняет — переменная цикла тоже копия. Лечится иммутабельностью структуры.
> - **Структура-ключ без `IEquatable<T>`.** Каждое сравнение в `Dictionary`/`HashSet` идёт через `ValueType.Equals(object)`: боксинг обоих операндов плюс, если в структуре есть ссылочные поля или паддинг, — перебор полей рефлексией. На сотне тысяч записей это на порядок медленнее.
> - **`default(T)` для структуры не вызывает конструктор.** Только обнуление байтов. Если у типа есть невалидное нулевое состояние (например, обязательная непустая строка) — структура для него не подходит.
> - **Агент часто:** пишет generic-метод с `T` в сигнатуре, но приводит параметр к интерфейсу вместо ограничения (`where T : IEquatable<T>` / `IComparable<T>`) — на значимом типе это боксинг на каждый вызов, незаметный без профилировщика или взгляда на IL.
> - **Агент часто:** логирует или форматирует значения через `string.Format`/старые `params object[]`-перегрузки вместо интерполяции — забывая, что именно `string.Format` (в отличие от `$"..."` с C# 10) всё ещё боксит каждый значимый аргумент.

## Проверка на ревью

- В generic-коде над значимыми типами есть нужный constraint (`where T : IEquatable<T>`), а не голый `object`/интерфейс без ограничения.
- Структура, которая сравнивается, кладётся в `Dictionary`/`HashSet` или проверяется в LINQ, реализует `IEquatable<T>` или объявлена как `record struct`.
- Мутабельные структуры не хранятся как публичные свойства с расчётом, что элемент можно менять «на месте» через `foreach` или через геттер свойства.
- Большие (>16 байт) структуры в горячих путях принимаются по `in`/`ref`, а не по значению.
- В логировании и форматировании горячего пути нет `params object[]` со значимыми аргументами без проверки, что это не боксит (интерполяция C# 10+ — не боксит, `string.Format` — боксит).
- Новый `struct` спроектирован так, что `default` — валидное состояние.

## Проверь себя

> [!question]- В чём принципиальная разница между значимым и ссылочным типом?
> Переменная значимого типа содержит сами данные, переменная ссылочного — адрес объекта в куче. Отсюда разница в присваивании (копия данных против копии адреса), в значении по умолчанию (обнулённые поля против `null`) и в равенстве по умолчанию (по полям против по ссылке).

> [!question]- Правда ли, что структуры всегда лежат на стеке?
> Нет. Значимый тип живёт там, где объявлен владелец: поле класса, элемент массива, боксированное значение и переменная, захваченная замыканием или пережившая `await` в `async`-методе, — всё это куча. На стеке лежат только локальные переменные, которые не подверглись ни одному из этих случаев.

> [!question]- Почему боксинг — это аллокация, а не «просто приведение типа»?
> Потому что рантайму нужно поместить значение туда, где CLR ожидает ссылку на объект с заголовком (sync block + MethodTable). Он создаёт новый объект в куче, копирует туда байты значения и возвращает адрес. Это ровно тот же путь, что и `new` для класса — с теми же 24 байтами минимума и той же будущей работой GC.

> [!question]- Почему `ValueType.Equals` считается медленным для структур без `IEquatable<T>`?
> Он принимает `object`, то есть боксит оба сравниваемых значения. Дальше, если структура плотно упакована и не содержит ссылок, идёт быстрое побитовое сравнение; иначе — медленный путь через рефлексию по полям. Реализация `IEquatable<T>` (вручную или через `record struct`) даёт типизированный `Equals`, который вызывается без боксинга и без рефлексии.

> [!question]- Когда осознанно нарушают правило «struct — маленький и иммутабельный»?
> Для больших `readonly struct`, которые хранят в массиве и всегда передают по `in`/`ref` — например, в вычислительных ядрах (обработка изображений, физика, парсинг протоколов). Выигрыш там не от отсутствия аллокаций, а от непрерывности данных и локальности кеша процессора при обходе массива.

## Разбор

### Разбор 1. Скрытый боксинг в generic-коде

Метод вызывается миллион раз в секунду, профилировщик показывает аллокации:

```csharp
public interface IValidator { bool IsValid(int value); }
public readonly struct RangeValidator(int min, int max) : IValidator
{
    public bool IsValid(int value) => value >= min && value <= max;
}

public static int CountValid(ReadOnlySpan<int> data, IValidator validator)
{
    int count = 0;
    foreach (var x in data) if (validator.IsValid(x)) count++;
    return count;
}
```

> [!success]- Решение
> `IValidator validator` — параметр типа интерфейса, поэтому `RangeValidator` (структура) боксится при каждом вызове `CountValid`, а вызовы `IsValid` внутри цикла становятся виртуальными и не встраиваются.
> ```csharp
> public static int CountValid<TValidator>(ReadOnlySpan<int> data, TValidator validator)
>     where TValidator : IValidator
> {
>     int count = 0;
>     foreach (var x in data) if (validator.IsValid(x)) count++;
>     return count;
> }
> ```
> JIT создаёт отдельную специализацию под `RangeValidator`: значение передаётся без боксинга, вызов `IsValid` разрешается статически (`constrained call`) и обычно встраивается. Цена — рост размера кода на каждый значимый тип-аргумент; для двух-трёх реализаций это выгодно.

### Разбор 2. PR агента: структура как ключ словаря

Ревьюер видит PR с новым типом и его использованием:

```csharp
public struct OrderKey { public int WarehouseId; public long OrderNo; }

var cache = new Dictionary<OrderKey, Order>();
cache[new OrderKey { WarehouseId = 1, OrderNo = 42 }] = order;
```

Что вернуть на доработку?

> [!success]- Решение
> `OrderKey` не реализует `IEquatable<T>`, поэтому `Dictionary<OrderKey, Order>` использует `EqualityComparer<OrderKey>.Default`, который падает на `ValueType.Equals(object)` — боксинг обоих операндов на каждую операцию плюс медленный путь сравнения, если в будущем в структуру добавят ссылочное поле. На словаре в проде это заметная деградация под нагрузкой.
> ```csharp
> public readonly record struct OrderKey(int WarehouseId, long OrderNo);
> ```
> Компилятор сгенерирует `IEquatable<OrderKey>`, `GetHashCode` по всем полям и `==`/`!=` — без единой аллокации на сравнение, и `Dictionary` подхватит типизированную версию автоматически.

## Итог

- Значимый тип хранит данные в переменной, ссылочный — адрес объекта в куче; всё остальное — следствие этого.
- Место в памяти определяет владелец, а не категория типа: «структуры на стеке» — неверное упрощение, структура-поле, структура-элемент массива и боксированная структура живут в куче.
- Боксинг — та же операция, что создание объекта класса: аллокация плюс заголовок (16 байт) плюс копия данных, только источник — уже существующее значение.
- Боксинг чаще всего неявный: приведение к `object`/интерфейсу, `params object[]`, `ValueType.Equals` на структуре без `IEquatable<T>`.
- Дженерики с ограничениями (`where T : IEquatable<T>`) убирают боксинг и виртуальный вызов через специализацию JIT — это основной инструмент борьбы, не `object`.
- По умолчанию `class`; `struct`/`readonly record struct` — осознанный выбор под маленькое иммутабельное значение или замеренную горячую точку.
