**Фактические возможности C# 14** (проверено по Microsoft Learn — не выдумывай другие):
- Extension members — новый синтаксис `extension(Type receiver) { ... }`, позволяет extension-свойства, статические extension-члены, extension-операторы
- Ключевое слово `field` — доступ к автогенерируемому backing field в аксессоре свойства
- Null-conditional assignment — `customer?.Order = x;` работает слева от `=` и составных присваиваний (`++`/`--` НЕ поддерживаются)
- `nameof` для несвязанных дженериков: `nameof(List<>)` → `"List"`
- Больше неявных преобразований `Span<T>`/`ReadOnlySpan<T>`/`T[]`
- Модификаторы (`ref`, `out`, `in`, `scoped`, `ref readonly`) у параметров лямбд без указания типа. `params` по-прежнему требует типа
- `partial` конструкторы и события
- Пользовательские операторы составного присваивания
- Директивы препроцессора для file-based приложений (`dotnet run app.cs`)

**C# 15 (preview, .NET 11):** union-типы (unions) — главная фича. Runtime Async. CoreCLR для WebAssembly. Упоминать только в разделе «что впереди».

**Ключевое в .NET 10 по темам:**
- ASP.NET Core 10: валидация в Minimal API через `AddValidation()` + DataAnnotations; OpenAPI **3.1 по умолчанию** и генерация из XML-комментариев через source generator, YAML-вывод; `TypedResults.ServerSentEvents`; passkeys/WebAuthn в Identity; cookie-аутентификация возвращает 401/403 вместо редиректа для API-эндпоинтов; метрики аутентификации/авторизации; поддержка `.localhost` TLD; Microsoft.OpenApi 2.0
- EF Core 10: complex types с маппингом в JSON и поддержкой struct; опциональные complex types; **новый режим параметризованных коллекций по умолчанию** (каждое значение — отдельный скалярный параметр с паддингом, вместо `OPENJSON`); поддержка LINQ-операторов `LeftJoin`/`RightJoin` (новые в .NET 10); **именованные фильтры запросов** `HasQueryFilter("Имя", ...)` + `IgnoreQueryFilters(["Имя"])`; `ExecuteUpdateAsync` принимает обычную (не-expression) лямбду; `ExecuteUpdateAsync` для JSON-колонок; vector search и JSON-тип для SQL Server 2025/Azure SQL; редактирование инлайновых констант в логах по умолчанию; анализатор на конкатенацию в raw SQL; более согласованная сортировка в split-запросах
- .NET 10 рантайм: JIT использует AVX-512/AVX10.2/ARM SVE2, выигрыш 15–30 %

Если не уверен в факте — проверь через WebSearch/WebFetch на learn.microsoft.com. **Лучше не написать, чем написать неверно.** Не выдумывай API, сигнатуры и номера версий.

## 2. Формат файла

Каждая заметка — `.md` с YAML-фронтматтером:

```markdown
---
tags: [раздел-XX, тема, основы|middle, собес]
aliases: [Альтернативное название, English name]
---

# Название заметки

> [!abstract] Коротко
> 2–4 предложения: что это и зачем нужно. Человек должен понять суть, не читая дальше.

...основной текст...
```

Правила фронтматтера:
- `tags` — обязателен. Всегда включай тег раздела (`раздел-06`). Добавляй по смыслу: `основы`, `middle`, `собес`, `подводный-камень`, `dotnet10`, `устарело`
- `aliases` — обязателен, минимум английский эквивалент термина (чтобы поиск находил и по `async`, и по «асинхронность»)

## 3. Структура основного текста

Обязательные секции в этом порядке (пропускай только те, что реально неприменимы):

1. **`> [!abstract] Коротко`** — суть в 2–4 предложениях
2. **Зачем это нужно** — какую задачу решает, что было до/без этого
3. **Теория** — разделы `##` и `###`. Объясняй *механику*, а не пересказывай справку. Отвечай на «почему так», а не только «как»
4. **Код** — примеры в ```csharp. Каждый пример должен компилироваться. Комментарии по-русски. Показывай вывод там, где он неочевиден: `// Вывод: 42`
5. **`> [!warning] Подводные камни`** — минимум 2–3 реальные ловушки с объяснением *почему* так происходит
6. **`> [!example] Как делают в бою`** — практика продакшена, если применимо
7. **`## Вопросы с собеседований`** — 4–8 вопросов. Формат: вопрос, затем свёрнутый ответ:
   ```markdown
   > [!question]- Чем `Task` отличается от `Thread`?
   > Развёрнутый ответ на 3–6 предложений, с кодом при необходимости.
   ```
   Ответ должен быть настоящим, полным, а не отпиской.
8. **`## Задачи`** — 2–5 задач. Условие, затем решение в свёрнутом блоке:
   ```markdown
   ### Задача 1. Название
   Условие задачи.

   > [!success]- Решение
   > ```csharp
   > // код
   > ```
   > Пояснение, почему так.
   ```
9. **`## Итог`** — 3–6 пунктов-тезисов для быстрого повторения
10. **`## Связанное`** — список `[[wikilink]]` на 3–8 соседних заметок

## 4. Вики-ссылки

- Синтаксис: `[[Точное имя файла без .md]]`. Регистр и пробелы — важны.
- **Используй ТОЛЬКО имена из выданного тебе манифеста.** Не придумывай новые имена файлов — ссылка не разрешится.
- Ссылайся плотно: в теле текста при первом упоминании термина из другой заметки + блок «Связанное» в конце.
- Ссылка на файл в другой папке пишется так же — просто по имени: `[[Boxing и unboxing]]`.

## 5. Callout-блоки Obsidian

Используй активно, они делают базу читаемой:
- `> [!abstract] Коротко` — резюме сверху
- `> [!info]` — дополнительный контекст
- `> [!tip]` — совет
- `> [!warning] Подводные камни` — ловушки
- `> [!danger]` — то, что ломает прод
- `> [!question]-` — вопрос собеса (минус = свёрнут)
- `> [!success]-` — решение задачи (свёрнуто)
- `> [!example]` — пример из практики
- `> [!quote]` — цитата из спеки/документации

## 6. Тон и качество

- Пиши как опытный инженер для коллеги, а не как учебник для школьника. Без воды, без «в этой статье мы рассмотрим».
- Не бойся глубины: цель — Middle 2. Где уместно, показывай IL, ассемблер, внутренности рантайма.
- Обязательно показывай **эволюцию**: «раньше делали так → сейчас так → потому что».
- Помечай устаревшее тегом `#устарело` и объясняй, почему от этого ушли (человек встретит это в легаси).
- Таблицы для сравнений — обязательны, они лучше абзацев.
- ASCII-диаграммы приветствуются для процессов и структур памяти.
- Объём: **250–600 строк** на заметку в зависимости от важности темы. Ключевые темы (async/await, GC, DI, EF Core performance) — ближе к верхней границе. Не раздувай ради объёма.

## 7. Чего НЕ делать

- ❌ Не ссылайся на внешние URL как на источник знания («подробнее читайте в документации»). База должна быть **самодостаточной** — объясни прямо здесь. Внешние ссылки допустимы только как «куда копать глубже» в конце.
- ❌ Не пиши «TODO», «здесь будет», заглушки, незавершённые примеры.
- ❌ Не дублируй содержимое соседних заметок — ссылайся.
- ❌ Не выдумывай API, методы и версии.
- ❌ Не используй эмодзи в тексте (кроме заголовков файлов, где они уже есть в имени).
