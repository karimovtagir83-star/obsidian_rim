# Настройка окружения

> [!abstract] Коротко
> За один вечер: .NET 10 SDK, редактор, Git, Docker с PostgreSQL. В конце — проверочный чек-лист. Инструкции для **Linux** (основная система), с пометками для Windows и macOS.

| Инструмент | Зачем | Обязательно? |

| .NET 10 SDK | Компилятор, рантайм, CLI | ✅ да |
| Редактор (Rider / VS Code / VS) | Писать код | ✅ да |

## 1. .NET 10 SDK

Целевая версия — **.NET 10 LTS** (поддержка до 10 ноября 2028). Ставить надо именно **SDK**, а не только рантайм: SDK включает компилятор и CLI.

### Arch Linux / CachyOS

```bash
sudo pacman -S dotnet-sdk aspnet-runtime
```

Проверь, что версия десятая:

```bash
dotnet --version        # ожидаем 10.x.x
dotnet --list-sdks
```

Если в репозитории пакет старее, ставь официальным скриптом (не требует root, кладёт в домашний каталог):

```bash
curl -sSL https://dot.net/v1/dotnet-install.sh | bash -s -- --channel 10.0
```

Затем добавь в PATH. Твоя оболочка — **fish**, поэтому:

```fish
fish_add_path $HOME/.dotnet
set -Ux DOTNET_ROOT $HOME/.dotnet
```

> [!info] Для других систем
> - **Ubuntu/Debian:** `sudo apt install dotnet-sdk-10.0` (может понадобиться репозиторий Microsoft)
> - **Windows:** скачай инсталлятор с dotnet.microsoft.com или `winget install Microsoft.DotNet.SDK.10`
> - **macOS:** `brew install --cask dotnet-sdk`

### Отключить телеметрию (по желанию)

```fish
set -Ux DOTNET_CLI_TELEMETRY_OPTOUT 1
```

### Проверка

```bash
mkdir -p ~/dev/hello && cd ~/dev/hello
dotnet new console
dotnet run
# Hello, World!
```

Если увидел `Hello, World!` — SDK работает.

> [!tip] Файловые приложения (.NET 10)
> В .NET 10 можно запускать одиночный `.cs` без создания проекта:
> ```bash
> echo 'Console.WriteLine("Привет");' > test.cs
> dotnet run test.cs
> ```
> Удобно для проверки идей и решения задач из базы. Подробнее — в [[dotnet CLI: полный обзор]].

## 2. Редактор

Три варианта, в порядке удобства для .NET:

### JetBrains Rider — рекомендую

Лучший инструмент для .NET на Linux. Бесплатен для некоммерческого использования (с 2024 года).

```bash
# через Toolbox (удобнее для обновлений) или напрямую:
yay -S rider
```

Что включить сразу: `Settings → Editor → Inspection Settings` — поднять severity для nullable-предупреждений.

### VS Code — легковесный вариант

```bash
sudo pacman -S code   # или уже установленный vscode-oss
```

Обязательные расширения:
- **C# Dev Kit** (Microsoft) — язык, отладка, тесты
- **Docker**
- **PostgreSQL** (Chris Kolkman) или **Database Client**

> [!warning] C# Dev Kit и OSS-сборки
> C# Dev Kit лицензионно привязан к официальным сборкам VS Code. В `vscode-oss` (Code — OSS) он может не установиться из Marketplace. Варианты: поставить официальный `visual-studio-code-bin` из AUR, либо использовать открытое расширение **C#** (ms-dotnettools.csharp) с OmniSharp/Roslyn LSP, либо взять Rider.

### Visual Studio 2026 — только Windows

Самый полный набор инструментов (профилировщики, диагностика), но недоступен на Linux.

## 3. Git

```bash
sudo pacman -S git
git config --global user.name "Твоё Имя"
git config --global user.email "rim.karimov@alif.uz"
git config --global init.defaultBranch main
git config --global core.editor "nvim"   # или code --wait
git config --global pull.rebase true
```

### Репозиторий для обучения

Создай один репозиторий на всё обучение — он же станет дневником прогресса:

```bash
mkdir -p ~/dev/csharp-learning && cd ~/dev/csharp-learning
git init
dotnet new gitignore     # готовый .gitignore для .NET
git add . && git commit -m "chore: начало обучения"
```

Дальше — папка на тему: `01-basics/`, `02-oop/` и так далее. Коммить ежедневно.

Подробнее — [[Git: рабочий минимум]].

## 4. Docker

Нужен с 5-го этапа, но поставь заранее.

```bash
sudo pacman -S docker docker-compose
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
```

Перелогинься (или `newgrp docker`), затем проверь:

```bash
docker run --rm hello-world
```

### PostgreSQL + Redis одной командой

Создай `~/dev/infra/compose.yaml`:

```yaml
services:
  postgres:
    image: postgres:18
    container_name: learn-postgres
    environment:
      POSTGRES_USER: dev
      POSTGRES_PASSWORD: dev
      POSTGRES_DB: learning
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U dev -d learning"]
      interval: 5s
      timeout: 5s
      retries: 5

  redis:
    image: redis:8-alpine
    container_name: learn-redis
    ports:
      - "6379:6379"

  # Просмотр логов приложения в браузере — пригодится с 6-го этапа
  seq:
    image: datalust/seq:latest
    container_name: learn-seq
    environment:
      ACCEPT_EULA: "Y"
    ports:
      - "5341:5341"   # приём логов
      - "8081:80"     # веб-интерфейс

volumes:
  pgdata:
```

Запуск и остановка:

```bash
cd ~/dev/infra
docker compose up -d          # поднять
docker compose ps             # статус
docker compose logs -f postgres
docker compose down           # остановить (данные сохранятся в volume)
docker compose down -v        # остановить и стереть данные
```

Строка подключения для .NET:

```
Host=localhost;Port=5432;Database=learning;Username=dev;Password=dev
```

> [!danger] Пароли только для локальной разработки
> `dev/dev` допустим исключительно на своей машине. Никогда не коммить реальные строки подключения — см. [[Секреты: Key Vault, переменные, что нельзя в Git]].

Подробнее — [[Docker: основы]] и [[Docker Compose]].

## 5. Инструменты диагностики

Понадобятся с 3-го этапа (память, GC) и станут основными на 9-м.

```bash
dotnet tool install -g dotnet-counters   # живые метрики процесса
dotnet tool install -g dotnet-dump       # снятие и анализ дампов
dotnet tool install -g dotnet-trace      # трассировка производительности
dotnet tool install -g dotnet-gcdump     # снимок управляемой кучи
dotnet tool install -g dotnet-ef         # миграции EF Core (нужен с 5-го этапа)
```

Добавь в PATH:

```fish
fish_add_path $HOME/.dotnet/tools
```

Проверка: `dotnet-counters --version`

Как этим пользоваться — [[Диагностика в проде: дампы и dotnet-tools]].

## 6. Дополнительно

### Клиент для API (с 6-го этапа)

- **Bruno** — открытый, файлы запросов хранятся в репозитории рядом с кодом. Рекомендую: `yay -S bruno-bin`
- **Postman** — популярнее, но требует аккаунт и облако
- **curl / httpie** — для быстрых проверок из терминала
- Или встроенные `.http`-файлы: и Rider, и VS Code (расширение REST Client) умеют выполнять запросы прямо из файла в проекте

### Просмотр IL и декомпиляция (с 3-го этапа)

- **ILSpy** (`yay -S avaloniailspy` — кроссплатформенная версия) — читать IL и декомпилированный C#
- **sharplab.io** — онлайн: показывает IL и то, во что компилятор разворачивает синтаксический сахар. Незаменимо при изучении [[async и await: как это работает на самом деле]] и [[IEnumerable, IEnumerator и yield return]]

### Обсидиан

Эта база — сам Обсидиан. Полезные плагины перечислены в [[Как пользоваться базой]].

## Глобальные настройки для всех проектов

Создай `~/dev/Directory.Build.props` — он подхватится всеми проектами в подпапках и включит строгий режим сразу:

```xml
<Project>
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <TreatWarningsAsErrors>true</TreatWarningsAsErrors>
    <EnableNETAnalyzers>true</EnableNETAnalyzers>
    <AnalysisLevel>latest-recommended</AnalysisLevel>
    <LangVersion>latest</LangVersion>
  </PropertyGroup>
</Project>
```

> [!tip] Зачем `TreatWarningsAsErrors` с первого дня
> Предупреждения, которые можно игнорировать, игнорируются всегда. Превратив их в ошибки, ты приучаешься писать чисто с самого начала — и особенно это касается nullable-предупреждений. Первую неделю будет раздражать, дальше станет незаметно.

Подробнее про этот файл — [[Файл проекта .csproj изнутри]].

## Проверочный чек-лист

Окружение готово, когда всё выполняется без ошибок:

- [ ] `dotnet --version` → `10.x.x`
- [ ] `dotnet new console && dotnet run` → выводит `Hello, World!`
- [ ] `dotnet run test.cs` работает (файловые приложения .NET 10)
- [ ] Редактор открывает проект, работают автодополнение и отладчик (поставь точку останова и попади в неё)
- [ ] `git log` показывает первый коммит в учебном репозитории
- [ ] `docker compose up -d` поднимает postgres, redis, seq
- [ ] Подключение к PostgreSQL работает: `docker exec -it learn-postgres psql -U dev -d learning -c "SELECT version();"`
- [ ] Seq открывается на `http://localhost:8081`
- [ ] `dotnet-counters --version` отвечает
- [ ] `~/dev/Directory.Build.props` создан

## Типичные проблемы

> [!warning] Что чаще всего ломается
> **`dotnet` не найден после установки скриптом** — не добавлен PATH. Для fish: `fish_add_path $HOME/.dotnet` и перезапусти оболочку.
>
> **`permission denied` в Docker** — не перелогинился после `usermod -aG docker`. Проверь `groups | grep docker`.
>
> **Порт 5432 занят** — в системе уже стоит PostgreSQL. Либо останови его (`sudo systemctl stop postgresql`), либо смени порт в compose на `5433:5432`.
>
> **Отладчик не останавливается на точке останова** — собрана Release-конфигурация. Убедись, что запускаешь Debug.
>
> **Несколько SDK, берётся не тот** — создай `global.json` в корне: `dotnet new globaljson --sdk-version 10.0.100`.
>
> **Rider/VS Code не видят SDK** — укажи путь вручную в настройках toolchain, либо задай `DOTNET_ROOT`.
