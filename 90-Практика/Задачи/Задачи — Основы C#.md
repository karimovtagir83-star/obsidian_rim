# Задачи — Основы C#

> [!abstract] Коротко
> 80 задач по блоку «Синтаксис и типы» и «Современный C#»: типы и литералы, операторы, преобразования, ветвление и паттерны, циклы, методы, замыкания, работа с `null`, записи и перечисления, исключения. Решение у каждой задачи свёрнуто — открывай только после своей попытки. Задачи на строки и массивы вынесены отдельно: [[Задачи — Строки и массивы]].

> [!tip] Как решать
> 1. Сначала пиши решение сам, в редакторе, и **запускай** — не «в уме».
> 2. Открыл решение и оно совпало — отлично; не совпало — разберись, почему авторский вариант такой, и перепиши свой.
> 3. Через неделю вернись к разделу и перерешай задачи, которые вызвали трудность. Это и есть интервальное повторение из [[Как пользоваться базой]].
> 4. Задачи вида «что выведет» решай **до** запуска: ценность в предсказании, а не в проверке.

Все примеры рассчитаны на .NET 10 / C# 14 с `<Nullable>enable</Nullable>` и `<ImplicitUsings>enable</ImplicitUsings>`.

## 1. Типы и литералы

### 1.1. Границы типов
Выведи минимальное и максимальное значение `int`, `long`, `decimal` и размер каждого в байтах.

> [!success]- Решение
> ```csharp
> Console.WriteLine($"int: {int.MinValue}..{int.MaxValue}, {sizeof(int)} байт");
> Console.WriteLine($"long: {long.MinValue}..{long.MaxValue}, {sizeof(long)} байт");
> Console.WriteLine($"decimal: {decimal.MinValue}..{decimal.MaxValue}, {sizeof(decimal)} байт");
> ```
> `sizeof` работает для значимых типов без `unsafe` начиная с C# 2 для встроенных типов. У `decimal` 16 байт при точности 28–29 знаков.

### 1.2. Тип литерала
Что за тип у `var a = 42;`, `var b = 42L;`, `var c = 4.2;`, `var d = 4.2m;`, `var e = 'A';`? Проверь через `GetType()`.

> [!success]- Решение
> ```csharp
> Console.WriteLine(42.GetType());      // System.Int32
> Console.WriteLine(42L.GetType());     // System.Int64
> Console.WriteLine(4.2.GetType());     // System.Double  — дробный литерал по умолчанию double
> Console.WriteLine(4.2m.GetType());    // System.Decimal
> Console.WriteLine('A'.GetType());     // System.Char
> ```
> Главный вывод: дробный литерал без суффикса — `double`, поэтому `decimal price = 4.2;` не компилируется.

### 1.3. Деньги
Посчитай стоимость 3 товаров по 19,99 и покажи, чем отличается результат в `double` и `decimal`.

> [!success]- Решение
> ```csharp
> double d = 19.99 * 3;
> decimal m = 19.99m * 3;
> Console.WriteLine(d.ToString("G17"));   // 59,969999999999999
> Console.WriteLine(m);                    // 59,97
> ```
> `double` хранит двоичную дробь, 19,99 в ней непредставима точно. Для денег — только `decimal`.

### 1.4. Значения по умолчанию
Выведи `default` для `int`, `bool`, `string?`, `DateTime`, `Guid` и `int?`.

> [!success]- Решение
> ```csharp
> Console.WriteLine(default(int));        // 0
> Console.WriteLine(default(bool));       // False
> Console.WriteLine(default(string?) is null);   // True
> Console.WriteLine(default(DateTime));   // 01.01.0001 0:00:00
> Console.WriteLine(default(Guid));       // 00000000-0000-0000-0000-000000000000
> Console.WriteLine(default(int?) is null);      // True
> ```
> `DateTime` по умолчанию — год 1, а не `null` и не «сейчас»: отсюда правило использовать `DateTime?` для необязательных дат.

### 1.5. Разделители и системы счисления
Запиши число 1 000 000 тремя способами: десятичным с разделителями, шестнадцатеричным и двоичным. Проверь равенство.

> [!success]- Решение
> ```csharp
> int a = 1_000_000;
> int b = 0x0F_4240;
> int c = 0b1111_0100_0010_0100_0000;
> Console.WriteLine(a == b && b == c);   // True
> ```
> Подчёркивания игнорируются компилятором и нужны только глазам.

### 1.6. Nullable значимого типа
Объяви `int?`, присвой `null`, безопасно получи значение или −1, затем присвой 5 и выведи `Value`.

> [!success]- Решение
> ```csharp
> int? maybe = null;
> Console.WriteLine(maybe ?? -1);              // -1
> Console.WriteLine(maybe.GetValueOrDefault(-1));  // -1
> maybe = 5;
> Console.WriteLine(maybe.HasValue ? maybe.Value : -1);   // 5
> ```
> Обращение к `.Value` при `HasValue == false` даёт `InvalidOperationException`, поэтому используют `??` или `GetValueOrDefault`.

### 1.7. Псевдоним типа
Заведи псевдоним `Money` для `decimal` и `Coordinates` для кортежа `(double Lat, double Lon)`, используй оба.

> [!success]- Решение
> ```csharp
> using Money = decimal;
> using Coordinates = (double Lat, double Lon);
>
> Money price = 19.99m;
> Coordinates office = (41.2995, 69.2401);
> Console.WriteLine($"{price} {office.Lat}");
> ```
> Псевдоним не создаёт нового типа: `Money` и `decimal` взаимозаменяемы, компилятор не запретит сложить деньги с процентами.

### 1.8. Какой тип выбрать
Для каждого поля выбери тип: идентификатор заказа, сумма, признак оплаты, дата оплаты (может отсутствовать), код валюты, количество попыток.

> [!success]- Решение
> ```csharp
> long OrderId;            // не int: заказы растут
> decimal Amount;          // деньги — всегда decimal
> bool IsPaid;
> DateTimeOffset? PaidAt;  // «не оплачен» выражено типом, а не DateTime.MinValue
> string Currency;         // лучше — enum или value object
> int AttemptCount;
> ```
> Ключевое: `long` для идентификаторов, `decimal` для денег, `Nullable` вместо магических значений, `DateTimeOffset` вместо `DateTime`.

## 2. Операторы и выражения

### 2.1. Что выведет
`Console.WriteLine(7 / 2); Console.WriteLine(7 % 2); Console.WriteLine(-7 / 2); Console.WriteLine(-7 % 2);`

> [!success]- Решение
> `3`, `1`, `-3`, `-1`. Целочисленное деление отбрасывает остаток и округляет к нулю; знак остатка берётся от делимого.

### 2.2. Среднее без переполнения
Напиши метод, вычисляющий среднее двух `int` без переполнения при больших значениях.

> [!success]- Решение
> ```csharp
> static int Average(int a, int b) => a + (b - a) / 2;
> Console.WriteLine(Average(int.MaxValue, int.MaxValue));   // 2147483647
> ```
> `(a + b) / 2` переполняется. Альтернатива — считать в `long`: `(int)(((long)a + b) / 2)`.

### 2.3. Кольцевой индекс
Реализуй `Prev(i, n)`, возвращающий предыдущий индекс по кругу (для `i == 0` это `n-1`).

> [!success]- Решение
> ```csharp
> static int Prev(int i, int n) => (i - 1 + n) % n;
> ```
> Прямое `(i - 1) % n` при `i == 0` даёт −1: остаток в C# наследует знак делимого.

### 2.4. Короткое замыкание
Что произойдёт: `if (order != null & order.IsPaid)` при `order == null`? А с `&&`?

> [!success]- Решение
> С `&` — `NullReferenceException`: оба операнда вычисляются всегда. С `&&` — правый операнд не вычисляется, условие безопасно возвращает `false`.

### 2.5. Приоритет битовых операторов
Почему `if (flags & Mask != 0)` не компилируется? Исправь.

> [!success]- Решение
> Приоритет `!=` выше, чем у `&`, поэтому сначала вычисляется `Mask != 0` (это `bool`), а `flags & bool` невозможен. Правильно: `if ((flags & Mask) != 0)`.

### 2.6. Цепочка null-операторов
Верни длину имени города клиента или 0, если по пути что-то `null`.

> [!success]- Решение
> ```csharp
> int len = order?.Customer?.Address?.City?.Length ?? 0;
> ```
> `?.` обрывает цепочку целиком при первом `null`, `??` подставляет значение по умолчанию.

### 2.7. Сравнение через object
Почему `(object)"abc" == (object)string.Concat("a", "bc")` даёт `False`, а `Equals` — `True`?

> [!success]- Решение
> `==` разрешается статически по типам операндов: для `object` это сравнение ссылок. `Equals` — виртуальный вызов, у `String` он сравнивает содержимое. В обобщённом коде используй `EqualityComparer<T>.Default`.

### 2.8. Инкремент в выражении
Что выведет: `int i = 1; Console.WriteLine(i++ + ++i);` и чему равно `i` после?

> [!success]- Решение
> Выведет `4` (1 + 3), `i` станет 3. Операнды вычисляются слева направо. В рабочем коде так писать нельзя — читаемость нулевая.

## 3. Приведение типов и переполнение

### 3.1. Тихое переполнение
Покажи, что `int.MaxValue + 1` не бросает исключение, и заставь его бросить.

> [!success]- Решение
> ```csharp
> int max = int.MaxValue;
> Console.WriteLine(max + 1);            // -2147483648
> Console.WriteLine(checked(max + 1));    // OverflowException
> ```
> По умолчанию контекст `unchecked`. Константное выражение `int.MaxValue + 1` не скомпилировалось бы вовсе.

### 3.2. Отбрасывание против округления
Сравни `(int)19.99`, `Convert.ToInt32(19.99)`, `Math.Round(19.99)`.

> [!success]- Решение
> `19`, `20`, `20`. Приведение отбрасывает дробную часть, `Convert` и `Math.Round` округляют.

### 3.3. Банковское округление
Почему `Math.Round(2.5)` даёт 2, а `Math.Round(3.5)` — 4? Как получить 3 из 2,5?

> [!success]- Решение
> По умолчанию используется округление к ближайшему чётному (IEEE 754). Нужное поведение: `Math.Round(2.5, MidpointRounding.AwayFromZero)` → 3.

### 3.4. Безопасный разбор
Разбери строку в `int`, вернув `-1` при неудаче, без исключений.

> [!success]- Решение
> ```csharp
> int value = int.TryParse(input, out var parsed) ? parsed : -1;
> ```
> `Parse` бросил бы исключение, `Convert.ToInt32(null)` тихо вернул бы 0.

### 3.5. Культура при разборе
Почему `double.Parse("19.99")` на сервере с русской локалью даёт 1999? Исправь.

> [!success]- Решение
> Точка воспринимается как разделитель групп разрядов. Правильно: `double.Parse("19.99", CultureInfo.InvariantCulture)`. Для машинных форматов культура указывается всегда.

### 3.6. Распаковка
Почему `(long)(object)42` бросает исключение? Исправь.

> [!success]- Решение
> Распаковать можно только в исходный тип: было упаковано `int`. Правильно — `(long)(int)(object)42`.

### 3.7. Составное присваивание и сужение
Что выведет: `byte b = 250; b += 50; Console.WriteLine(b);`?

> [!success]- Решение
> `44`. Составное присваивание содержит неявное приведение обратно к `byte`, и результат 300 переполняется по модулю 256.

### 3.8. Плавающее в целое
Что даст `(int)double.NaN` и `(int)1e20` в .NET 10?

> [!success]- Решение
> `0` и `2147483647`. С .NET 5 преобразования насыщающие и детерминированные; в `checked`-контексте оба выражения бросили бы `OverflowException`.

## 4. Ветвление и pattern matching

### 4.1. Категория возраста
Верни строку по возрасту: до 0 — исключение, до 18 — «несовершеннолетний», до 65 — «взрослый», иначе «пенсионер». Через `switch`-выражение.

> [!success]- Решение
> ```csharp
> static string Category(int age) => age switch
> {
>     < 0 => throw new ArgumentOutOfRangeException(nameof(age)),
>     < 18 => "несовершеннолетний",
>     < 65 => "взрослый",
>     _ => "пенсионер"
> };
> ```

### 4.2. Диапазон одной проверкой
Перепиши `if (x >= 0 && x <= 100)` паттерном.

> [!success]- Решение
> ```csharp
> if (x is >= 0 and <= 100) { }
> ```
> Читается как условие и исключает опечатку в имени переменной во второй части.

### 4.3. Набор значений
Перепиши `if (code == 400 || code == 404 || code == 409)` паттерном.

> [!success]- Решение
> ```csharp
> if (code is 400 or 404 or 409) { }
> ```

### 4.4. Свойственный паттерн
Проверь, что заказ оплачен, сумма больше 1000 и город клиента — «Ташкент», без проверок на `null`.

> [!success]- Решение
> ```csharp
> if (order is { Status: OrderStatus.Paid, Total: > 1000, Customer.Address.City: "Ташкент" }) { }
> ```
> Вложенный паттерн не бросает `NullReferenceException`: при `null` по пути он просто не совпадает.

### 4.5. Кортеж состояний
Опиши четыре комбинации `(isPaid, isShipped)` одним `switch`-выражением.

> [!success]- Решение
> ```csharp
> static string State(bool paid, bool shipped) => (paid, shipped) switch
> {
>     (true, true) => "завершён",
>     (true, false) => "готов к отправке",
>     (false, true) => "ошибка данных",
>     (false, false) => "ожидает оплаты"
> };
> ```
> Компилятор проверит полноту: ветвь `_` не нужна.

### 4.6. Списочный паттерн
Разбери массив аргументов: пусто → «список», `["add", текст]` → «добавить», остальное → «неизвестно».

> [!success]- Решение
> ```csharp
> static string Run(string[] args) => args switch
> {
>     [] => "список",
>     ["add", var item] => $"добавить {item}",
>     [var cmd, ..] => $"неизвестно: {cmd}",
>     _ => "ошибка"
> };
> ```

### 4.7. Фильтр when
Верни «просрочен», если заказ оплачен более 30 дней назад, иначе «оплачен» или «не оплачен».

> [!success]- Решение
> ```csharp
> static string Check(Order o, DateTimeOffset now) => o switch
> {
>     { Status: OrderStatus.Paid } when now - o.PaidAt > TimeSpan.FromDays(30) => "просрочен",
>     { Status: OrderStatus.Paid } => "оплачен",
>     _ => "не оплачен"
> };
> ```
> Порядок важен: более специфичная ветвь с `when` идёт первой.

### 4.8. Опасный `_`
Почему `_ => false` в `switch` по enum — потенциальный баг?

> [!success]- Решение
> Он отключает проверку полноты: при добавлении нового члена enum компилятор промолчит, и новое значение тихо попадёт в ветвь по умолчанию. Лучше перечислить все значения, а в `_` бросать исключение.

## 5. Циклы и итерация

### 5.1. FizzBuzz
Выведи числа 1–100, заменяя кратные 3 на «Fizz», кратные 5 на «Buzz», кратные 15 на «FizzBuzz».

> [!success]- Решение
> ```csharp
> for (int i = 1; i <= 100; i++)
>     Console.WriteLine((i % 3, i % 5) switch
>     {
>         (0, 0) => "FizzBuzz",
>         (0, _) => "Fizz",
>         (_, 0) => "Buzz",
>         _ => i.ToString()
>     });
> ```

### 5.2. Сумма цифр
Посчитай сумму цифр целого числа без преобразования в строку.

> [!success]- Решение
> ```csharp
> static int DigitSum(int n)
> {
>     n = Math.Abs(n);
>     int sum = 0;
>     while (n > 0) { sum += n % 10; n /= 10; }
>     return sum;
> }
> ```
> `Math.Abs(int.MinValue)` бросит исключение — для полной корректности принимай `long`.

### 5.3. Факториал и переполнение
Посчитай факториал 20 и 21 в `long`. Что происходит?

> [!success]- Решение
> ```csharp
> static long Factorial(int n)
> {
>     long result = 1;
>     for (int i = 2; i <= n; i++) result = checked(result * i);
>     return result;
> }
> ```
> 20! влезает в `long`, 21! — нет: без `checked` результат был бы тихо неверным.

### 5.4. Простые числа
Выведи все простые числа до 100.

> [!success]- Решение
> ```csharp
> for (int n = 2; n <= 100; n++)
> {
>     bool isPrime = true;
>     for (int d = 2; d * d <= n; d++)
>         if (n % d == 0) { isPrime = false; break; }
>     if (isPrime) Console.Write($"{n} ");
> }
> ```
> Проверка до `√n` вместо `n` сокращает работу с `O(n)` до `O(√n)` на число.

### 5.5. Модификация коллекции в цикле
Почему падает `foreach (var x in list) if (x < 0) list.Remove(x);`? Три способа исправить.

> [!success]- Решение
> `InvalidOperationException`: перечислитель проверяет версию коллекции. Способы: `list.RemoveAll(x => x < 0)`; обход копии `foreach (var x in list.ToList())`; обратный индексный цикл `for (int i = list.Count - 1; i >= 0; i--)`.

### 5.6. Захват переменной цикла
Почему все три лямбды из `for (int i = 0; i < 3; i++) actions.Add(() => Console.Write(i));` печатают 3? Исправь.

> [!success]- Решение
> Переменная `i` одна на весь цикл, лямбды захватили её саму. Исправление — копия внутри тела:
> ```csharp
> for (int i = 0; i < 3; i++) { int captured = i; actions.Add(() => Console.Write(captured)); }
> ```

### 5.7. Таблица умножения
Выведи таблицу умножения 9×9 с выравниванием колонок.

> [!success]- Решение
> ```csharp
> for (int i = 1; i <= 9; i++)
> {
>     for (int j = 1; j <= 9; j++) Console.Write($"{i * j,4}");
>     Console.WriteLine();
> }
> ```
> `,4` в интерполяции — выравнивание по правому краю на 4 символа.

### 5.8. Вынести инвариант
Что не так с `for (int i = 0; i < source.Count(); i++)` для `IEnumerable`?

> [!success]- Решение
> `Count()` перечисляет источник на каждой итерации — квадратичная работа, а для отложенного LINQ ещё и повторные запросы к базе. Нужно материализовать один раз: `var items = source.ToList();` и использовать `items.Count`.

## 6. Методы и параметры

### 6.1. Обмен значений
Напиши `Swap` для двух `int`.

> [!success]- Решение
> ```csharp
> static void Swap(ref int a, ref int b) => (a, b) = (b, a);
> ```
> Без `ref` метод менял бы копии.

### 6.2. Try-паттерн
Реализуй `TryDivide(int a, int b, out int result)`.

> [!success]- Решение
> ```csharp
> static bool TryDivide(int a, int b, out int result)
> {
>     if (b == 0) { result = 0; return false; }
>     result = a / b;
>     return true;
> }
> ```
> `out`-параметр обязан быть присвоен на всех путях выхода.

### 6.3. Что видно снаружи
Что выведет код, где метод меняет элемент массива, заменяет ссылку на массив, добавляет в список и заменяет ссылку на список?

> [!success]- Решение
> Изменения **содержимого** (элемент массива, `Add` в список) видны, замена ссылок — нет. Параметр содержит копию ссылки; чтобы заменить объект у вызывающего, нужен `ref`.

### 6.4. Несколько результатов
Верни минимум и максимум массива одним вызовом.

> [!success]- Решение
> ```csharp
> static (int Min, int Max) MinMax(int[] data)
> {
>     if (data.Length == 0) throw new ArgumentException("Пустой массив", nameof(data));
>     int min = data[0], max = data[0];
>     foreach (var x in data) { if (x < min) min = x; if (x > max) max = x; }
>     return (min, max);
> }
> var (lo, hi) = MinMax([3, 7, 1]);
> ```

### 6.5. Именованные аргументы
Сделай вызов `CreateUser("Иван", true, false, true)` читаемым.

> [!success]- Решение
> ```csharp
> CreateUser("Иван", isAdmin: true, isBlocked: false, sendEmail: true);
> ```
> Ещё лучше — заменить три `bool` на объект параметров или enum.

### 6.6. params без аллокации
Напиши метод суммы переменного числа аргументов, не создающий массив в куче.

> [!success]- Решение
> ```csharp
> static int Sum(params ReadOnlySpan<int> numbers)
> {
>     int total = 0;
>     foreach (var n in numbers) total += n;
>     return total;
> }
> ```
> `params ReadOnlySpan<T>` — C# 13: значения могут быть размещены на стеке.

### 6.7. Значение по умолчанию в библиотеке
Почему изменение `int timeout = 30` на `= 60` в NuGet-пакете не влияет на уже собранные приложения?

> [!success]- Решение
> Компилятор подставляет значение по умолчанию в **вызывающий** код при компиляции. Пока потребитель не пересоберётся, он продолжит передавать 30. Значение по умолчанию — часть публичного контракта.

### 6.8. Рекурсия против цикла
Почему `static long Sum(int n) => n == 0 ? 0 : n + Sum(n - 1);` падает при `n = 1_000_000`?

> [!success]- Решение
> `StackOverflowException`: каждый вызов кладёт кадр, стек ~1 МБ. Хвостовой оптимизации здесь нет (результат участвует в сложении), и поймать исключение нельзя. Нужен цикл.

## 7. Замыкания, делегаты, лямбды

### 7.1. Func и Action
Объяви делегат, возводящий число в квадрат, и делегат, печатающий строку.

> [!success]- Решение
> ```csharp
> Func<int, int> square = x => x * x;
> Action<string> print = Console.WriteLine;      // преобразование группы методов
> ```

### 7.2. Замыкание по значению
Что выведет код, где лямбда захватила переменную, а переменная потом изменилась?

> [!success]- Решение
> Новое значение: захватывается **переменная**, а не её значение. Компилятор поднимает её в поле скрытого класса замыкания.

### 7.3. Лямбда без захвата
Как гарантировать, что лямбда не создаёт аллокацию замыкания?

> [!success]- Решение
> ```csharp
> Func<int, int> f = static x => x * 2;
> ```
> `static` запрещает захват; если код компилируется, аллокации замыкания нет. Такая лямбда ещё и кешируется компилятором.

### 7.4. Многоадресный делегат
Что вернёт `Func<int>`, к которому подписаны три обработчика?

> [!success]- Решение
> Результат **последнего** вызванного обработчика; остальные теряются. Поэтому многоадресные делегаты с возвращаемым значением почти всегда ошибка.

### 7.5. Исключение в обработчике
Как вызвать всех подписчиков, даже если один бросает исключение?

> [!success]- Решение
> ```csharp
> foreach (var h in handlers.GetInvocationList().Cast<Action>())
>     try { h(); } catch (Exception ex) { errors.Add(ex); }
> ```
> Обычный вызов делегата прерывается на первом исключении.

### 7.6. Отписка от события
Почему `service.Event -= (s, e) => Handler();` не отписывает?

> [!success]- Решение
> Это новый экземпляр делегата: сравнение идёт по `Target` и `Method`, и такой обработчик в списке не найдётся. Нужно сохранить делегат в поле и передавать его же.

### 7.7. Утечка через событие
Почему подписка scoped-объекта на событие синглтона — утечка памяти?

> [!success]- Решение
> Делегат хранит ссылку на подписчика (`Target`), а издатель хранит делегаты. Пока жив синглтон, живы все подписчики. Лечение — отписка в `Dispose` или отказ от событий в пользу очереди.

### 7.8. Локальная функция против лямбды
Когда локальная функция лучше лямбды?

> [!success]- Решение
> Когда не нужен объект-делегат: локальная функция без захвата компилируется в обычный статический метод, без аллокаций. Плюс она может быть рекурсивной и использоваться до объявления. Лямбда нужна там, где значение передаётся как делегат.

## 8. null и Nullable reference types

### 8.1. Проверки на null
Три способа проверить `x` на `null`, и какой предпочтительнее.

> [!success]- Решение
> `x == null`, `x is null`, `ReferenceEquals(x, null)`. Предпочтительно `is null`: не зависит от перегрузки оператора `==`, работает в дженериках и читается однозначно.

### 8.2. Оператор ??=
Инициализируй поле кешем при первом обращении.

> [!success]- Решение
> ```csharp
> private List<string>? _cache;
> public List<string> Items => _cache ??= LoadItems();
> ```
> В многопоточном сценарии такой ленивой инициализации недостаточно — там `Lazy<T>`.

### 8.3. Проверка после вызова метода
Почему после `if (_field is not null) DoSomething();` компилятор снова предупреждает при использовании `_field`?

> [!success]- Решение
> Вызов метода мог изменить поле, и анализ потока сбрасывает знание о его состоянии. Правильно — скопировать в локальную переменную; это ещё и защита от гонки.

### 8.4. Опасность `!`
Что делает `value!` и когда это оправдано?

> [!success]- Решение
> Подавляет предупреждение компилятора, ничего не проверяя в рантайме. Оправдано в тестах (`null!`), для полей, заполняемых фреймворком, и там, где инвариант гарантирован, но не выводится компилятором. Массовое применение обесценивает NRT.

### 8.5. required вместо null!
Перепиши `public string Name { get; set; } = null!;` корректно.

> [!success]- Решение
> ```csharp
> public required string Name { get; init; }
> ```
> Компилятор потребует задать свойство при создании объекта.

### 8.6. Десериализация и NRT
Почему после `JsonSerializer.Deserialize<Request>("{}")` в не-nullable свойстве может оказаться `null`?

> [!success]- Решение
> NRT — только анализ компилятора, в рантайме проверок нет. Данные извне (JSON, БД, рефлексия) обходят его. Поэтому на границе системы нужна валидация.

### 8.7. TryGetValue и анализ потока
Почему после `if (dict.TryGetValue(key, out var value))` компилятор разрешает использовать `value` без проверки?

> [!success]- Решение
> Параметр аннотирован `[NotNullWhen(true)]`: компилятор знает, что при результате `true` значение не `null`.

### 8.8. Условие с nullable bool
Почему `if (customer?.IsActive)` не компилируется?

> [!success]- Решение
> Тип выражения — `bool?`, а `if` требует `bool`. Нужно `== true` или `is true` — и это заставляет явно решить, чем считать `null`.

## 9. Записи, структуры, enum, кортежи

### 9.1. Запись за одну строку
Опиши тип «деньги» с суммой и валютой, сравнением по значению и `with`.

> [!success]- Решение
> ```csharp
> public readonly record struct Money(decimal Amount, string Currency);
> var m = new Money(100, "UZS") with { Amount = 200 };
> ```

### 9.2. Равенство записей
Что выведет сравнение двух записей с одинаковыми полями и сравнение записи базового типа с наследником?

> [!success]- Решение
> Первое — `True` (сравнение по значению), второе — `False`: у записей есть `EqualityContract`, и типы должны совпадать.

### 9.3. Поверхностная копия
Почему после `var copy = original with { Id = 2 }; copy.Tags.Add("x");` меняется и оригинал?

> [!success]- Решение
> `with` копирует поля поверхностно: ссылка на список общая. Для настоящей независимости нужны иммутабельные коллекции (`ImmutableArray<T>`).

### 9.4. readonly record struct
Чем `record struct` отличается от `readonly record struct`?

> [!success]- Решение
> У обычного `record struct` позиционные свойства изменяемые (`get; set;`), у `readonly` — `get; init;`. Почти всегда нужен `readonly`: изменяемая структура ведёт себя неинтуитивно.

### 9.5. Значение по умолчанию enum
Почему в enum значение 0 должно быть осмысленным?

> [!success]- Решение
> `default(MyEnum)` всегда равен 0: несохранённая сущность, поле структуры, отсутствующее поле в JSON. Если под нулём числится `Deleted`, объекты по умолчанию окажутся удалёнными.

### 9.6. Флаги
Объяви права `Read`/`Write`/`Delete` и покажи добавление, снятие и проверку.

> [!success]- Решение
> ```csharp
> [Flags] enum Permissions { None = 0, Read = 1, Write = 2, Delete = 4, All = 7 }
> var r = Permissions.Read | Permissions.Write;
> bool canWrite = (r & Permissions.Write) != 0;
> r |= Permissions.Delete;
> r &= ~Permissions.Write;
> ```

### 9.7. Невалидное значение enum
Почему `(OrderStatus)999` компилируется и как защититься?

> [!success]- Решение
> В рантайме enum — просто число, приведение не проверяется. Защита: `Enum.IsDefined` для внешних значений и ветвь по умолчанию в `switch`, бросающая исключение с самим значением.

### 9.8. Деконструкция
Разбери кортеж и запись на переменные.

> [!success]- Решение
> ```csharp
> var (min, max) = MinMax(data);
> var (amount, currency) = new Money(100, "UZS");   // Deconstruct генерируется record'ом
> ```

## 10. Исключения и надёжность

### 10.1. throw против throw ex
В чём разница и что выбрать?

> [!success]- Решение
> `throw;` сохраняет исходный стек, `throw ex;` перезаписывает его с текущей строки. Всегда `throw;`; чтобы добавить контекст — обернуть: `throw new MyException("...", ex)`.

### 10.2. finally
Выполнится ли `finally` при `return` из `try`? А при исключении? А при `StackOverflowException`?

> [!success]- Решение
> Да, да, нет. `finally` не выполняется при переполнении стека, `Environment.FailFast` и внешнем убийстве процесса.

### 10.3. Фильтр исключений
Поймай `HttpRequestException` только со статусом 429.

> [!success]- Решение
> ```csharp
> catch (HttpRequestException ex) when (ex.StatusCode == HttpStatusCode.TooManyRequests) { }
> ```
> Фильтр вычисляется до разворачивания стека, в отличие от проверки внутри `catch`.

### 10.4. Guard-выражения
Перепиши проверки аргументов через помощники .NET.

> [!success]- Решение
> ```csharp
> ArgumentNullException.ThrowIfNull(order);
> ArgumentException.ThrowIfNullOrWhiteSpace(currency);
> ArgumentOutOfRangeException.ThrowIfNegativeOrZero(quantity);
> ```
> Имя параметра подставляется автоматически через `CallerArgumentExpression`.

### 10.5. Свой тип исключения
Спроектируй исключение «недостаточно средств» так, чтобы обработчик мог вернуть детали.

> [!success]- Решение
> ```csharp
> public sealed class InsufficientFundsException(long accountId, decimal requested, decimal available)
>     : Exception($"На счёте {accountId} недостаточно средств")
> {
>     public long AccountId { get; } = accountId;
>     public decimal Requested { get; } = requested;
>     public decimal Available { get; } = available;
> }
> ```
> Данные — в свойствах, а не в тексте сообщения.

### 10.6. Исключение или результат
Пользователь ввёл нечисловую строку в поле «количество». Исключение или результат?

> [!success]- Решение
> Результат: это ожидаемая ситуация из требований. `TryParse` и ответ 400 со списком ошибок. Исключение здесь и дорого, и семантически неверно.

### 10.7. Пустой catch
Чем плох `catch (Exception) { }` и что делать, если перехват действительно нужен?

> [!success]- Решение
> Ошибка исчезает бесследно, система продолжает работу в неопределённом состоянии. Если перехват нужен (цикл фоновой службы), внутри обязательно логирование объекта исключения и осознанное решение продолжать.

### 10.8. Логирование исключения
Почему `logger.LogError("Ошибка: " + ex.Message)` — плохо?

> [!success]- Решение
> Теряются тип, стек и внутренние исключения, а структурные поля не попадают в лог. Правильно: `logger.LogError(ex, "Не удалось обработать заказ {OrderId}", id)`.
